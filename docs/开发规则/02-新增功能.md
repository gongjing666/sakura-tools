# 02 新增功能

这一页是**动手清单**：从「我要加一个功能」到「它能上线」，按顺序走完即可。每一步都写了产物和验收判据；跳过某一步，问题会以「页面白屏」「保存后别的设置被清空」「升级后表不存在」的形式回来。

> 前置阅读：[01-架构与装配.md](01-架构与装配.md)。后台视觉部分见 [03-后台UI.md](03-后台UI.md)，数据部分见 [04-数据与存储.md](04-数据与存储.md)。

## 0. 先判断这是哪一类改动

| 类型 | 典型例子 | 主要落点 | 页签 |
|---|---|---|---|
| A. 纯后台设置项 | 新增一个压缩参数 | 设置仓储 + 卡片字段 + 渲染 | 无 |
| B. 新后台页面（React 岛） | 新增「统计」页 | Registry + 渲染器 + payload + React 源 + 岛挂载视图 + bundle + Layout | 有 |
| C. 后台异步动作 | 批量删除、扫描 | AJAX 或 REST + worker + 岛内调用 | 无 |
| D. 前台能力 | 快速检索、媒体库过滤 | 钩子 + 服务类 | 无 |
| E. 数据层 | 新表、新队列 | Schema + 迁移 + 卸载 | 视情况 |
| F. 新增 S3 存储厂商 | 接入一家新的对象存储 | Providers + Client_Factory + 连接页提示（见 §12） | 无 |

一个功能常常是几类的组合。**先写清楚它要落到哪几类，再动手**。

## 1. 决定落在哪个模块

现有五个模块、16 个页签，页面 id 的第一段就是模块 id：

| 模块 | 页面 id 前缀 | 页签 | 职责 |
|---|---|---|---|
| system | `system-` | settings | 环境自检、布局外观 |
| image | `image-` | rules / thumb / backup / stats | 压缩、缩略图、备份、统计 |
| storage | `storage-` | connection / sync / deletes / rewrite / cost | 对象存储连接、同步、删除队列、链接改写、费用估算 |
| files | `files-` | settings / users / queue / log / zibll | 用户文件空间 |
| zibll | `zibll-` | performance | 子比主题增强（主题侧集成） |

页面 id 由 `Route::page_id( $module, $tab )` 拼成 `{module}-{tab}`，它同时决定 `data-sakura-page`、页面 CSS、旧页脚本文件名和岛 bundle 的键。**这 16 个页签的内容区现在全部是 React 岛**（见 §6）——加页面不再是「加一个 PHP 视图」。

不属于任何模块的功能（前台、CLI、纯服务）就写成一个 `Module` 实现但不进 `Registry`。

**默认不要新建第六个模块**，除非它确实是一套独立的用户心智模型。加一个模块意味着多一个顶级菜单、多一套权限边界、多一份 `Layout::PAGES` 条目。1.28.7 的 `zibll` 模块就是按这条判据开的口子：它服务的对象是主题（子比）而不是本插件的存储/文件空间，和现有四个模块不共享任何设置或页面；它由 `zibll-site-enhance` 的功能逐步迁入，迁移一项就在这个模块里加一个页签。

## 2. 契约先行：写接口，再写实现

业务逻辑不要直接依赖 `$wpdb`、`WP_Filesystem` 或 `get_option()`。`src/Contracts/` 已有四个接口：

| 接口 | 用来隔离 |
|---|---|
| `Settings_Repository_Interface` | option 读写 |
| `Backup_Repository_Interface` | 备份文件 |
| `File_System_Interface` | 文件操作 |
| `Stats_Repository_Interface` | 统计数字 |

新功能如果碰这四类资源之一，**先看能不能扩展现有接口**。确实需要新的边界才新增接口文件（`src/Contracts/Xxx_Interface.php`）。

### 设置项：走 Settings_Repository

`src/Settings/Settings_Repository.php` 是 option 的唯一入口，类注释写得很清楚：

> WordPress still owns the rows and the Settings API still owns form registration/validation; this class owns the option names, defaults and typed reads so image/admin services do not call `get_option()` directly.

新增一个设置项要做四件事：

1. 在 `DEFAULTS` 常量里加 `'sakura_imgopt_xxx' => 默认值`；
2. 加一个带类型的读取方法（`quality()` 那种，内部做 `max( 1, min( 100, ... ) )` 之类的钳制）；
3. 在 `Activation::run()` 的默认 option 列表里补一条（否则激活时不会写入）；
4. 把字段描述符交给渲染层：岛页写进 `*_Payload::build()` 的字段数组（`type` / `label` / `hint` / `width` / `unit`…），由 `assets/ui/src/shared/ui.jsx` 的 `Field` 渲染；只有 bundle 缺失时的回退视图还用 `UI::field()`。

**不要**直接在视图里 `get_option( 'sakura_imgopt_xxx' )`；payload 里同样不读 `get_option()`，拿注入的 `Settings_Repository` 读法，前端只负责显示。

## 3. 服务类：单一职责，构造函数只存依赖

```php
final class My_Service {
    private Settings_Repository $settings;

    public function __construct( Settings_Repository $settings ) {
        $this->settings = $settings;   // 只赋值，不做 IO、不挂钩子
    }

    public function do_something( int $id ): array|WP_Error {
        // ...
    }
}
```

规则：

- **构造函数不做 IO、不挂钩子**（`Module` 契约的同一条理由：组合根要能决定装不装；测试要能在不启动 WP 的情况下检查钩子面）；
- 失败返回 `WP_Error`，不要抛异常穿透到 WordPress；
- 需要外部资源的（HTTP、文件系统、时钟）通过构造函数注入，方便测试。

## 4. 模块：实现 Module 接口

```php
namespace Sakura\ImageOptimizer\Image;

use Sakura\ImageOptimizer\Contracts\Module;
use Sakura\ImageOptimizer\Support\Hook_Loader;

final class My_Module implements Module {
    private My_Service $service;

    public function __construct( My_Service $service ) {
        $this->service = $service;
    }

    public function register_hooks( Hook_Loader $hooks ): void {
        $hooks->add_action( 'admin_init', array( $this, 'register_settings' ) );
        $hooks->add_action( 'wp_ajax_sakura_my_action', array( $this, 'ajax_do' ) );
    }

    public function register_settings(): void { /* register_setting(...) */ }
    public function ajax_do(): void { /* 见 §5 */ }
}
```

然后**在 `Plugin::build_modules()` 里按正确顺序 new 出来**：

- 依赖仓储或 `Image_Processor` 的，必须排在那 5 个仓储之后；
- 只用于后台的，放进 `is_admin()` 分支；
- 如果有 renderer，`Registry::register_renderer()` 必须早于 `Admin\Menu`（它永远最后）；`files` 模块的 renderer 例外，在 `src/UserFiles/Admin/Page::register_renderers()`（挂 `init`、优先级 20）。
- 岛页的 renderer 第一件事是判断 bundle 可读与否：可读 → 建 payload、`require` 岛挂载视图；不可读 → 走回退视图（见 §6.3）。

## 5. 后台异步动作（AJAX / REST）

命名与校验都要统一，照 `S3\Sync_Center_Module` 抄：

```php
$hooks->add_action( 'wp_ajax_sakura_my_action', array( $this, 'ajax_do' ) );

public function ajax_do(): void {
    if ( ! current_user_can( 'manage_options' ) ) {
        wp_send_json_error( array( 'message' => __( '权限不足。', 'sakura-imgopt' ) ), 403 );
    }
    check_ajax_referer( 'sakura_my_action', 'nonce' );

    $id = isset( $_POST['id'] ) ? absint( wp_unslash( $_POST['id'] ) ) : 0;
    // ... 调服务
    wp_send_json_success( array( 'done' => true ) );
}
```

规则：

- action 名一律 `sakura_` 前缀，与文件名、nonce 动作名保持可推导关系；
- **先查能力，再校验 nonce**（顺序在现有代码里一致，别混搭）；
- 输入一律 `absint` / `sanitize_key` / `wp_unslash`；
- 返回 `wp_send_json_success` / `wp_send_json_error`，错误带 HTTP 状态码与 `message`；
- 需要 `nopriv` 的只有前台场景，后台动作**不要**挂 `wp_ajax_nopriv_`。

前端调用走 `admin.api.ajax( action, data, options )`，它自动拼 action 名与 nonce，并从 `payload.data` 解包。岛里也直接用它（同步中心、链接改写、费用估算都还是），所以存量 AJAX 动作不必为了迁岛重写接口。

**新增的写入优先走 REST**（`/wp-json/sakura-tools/v1/…`，带 `X-WP-Nonce`），保存后不整页跳转。REST 路由**必须挂在无条件装配的模块上**：`/wp-json/` 请求不是后台页面，`is_admin()` 里装配的模块所注册的 `rest_api_init` 根本不执行，症状是保存 404。现有的 `Admin\Rest\System_Routes` / `Image_Routes` / `Storage_Routes` 都为此单列在 `Plugin::build_modules()` 末尾。

### 长任务：交给 worker，不要占着请求

超过约 10 秒的工作必须拆成：

1. AJAX 只做「启动」，立刻返回 job id 与初始进度；
2. worker 用 cron 钩子推进（参考 `Action_Worker`、`Scan_Worker`、`Delete_Worker`）；
3. 前端轮询另一个「读进度」的 AJAX。

**新加的 cron 钩子必须同时写进 `Deactivation::run()`**，否则停用后它还在跑（审计 B12 就是这个问题）。

## 6. 后台页面：加一个页签 = 加一个 React 岛

后台 16 个页签的内容区全部由 React 岛接管：PHP 只打印根节点、顶栏、页签条、页头与首帧骨架，卡片和交互由 `assets/ui/src/` 打出的 bundle 渲染（分工边界、DOM 契约与验收见 [03-后台UI.md](03-后台UI.md) §9.3–§9.4，写法见 [12-React代码规范.md](12-React代码规范.md)）。所以「加页面」是两层：**路由与外壳 4 处、岛本体 5 处**。`AGENTS.md` §2 用「六处」概括（payload 与挂载视图、登记与入队各并作一处）；这里展开成 9 个落点，因为 React 源和 bundle 也各是一处，漏了同样白屏。

### 6.1 路由与外壳：四处必改

漏一个就会出现「菜单里有但点进去空白」或「卡片挤成一列」：

1. **`Registry::modules()`**：在对应模块的 `tabs` 里加一项（`label` + 可选 `gate`）。tab id 同时是页面 id 的后半段。
2. **渲染器注册**：`Registry::register_renderer( 'image', 'mytab', array( $this, 'render_mytab' ) )`，必须早于 `Admin\Menu`（它永远最后）。`files` 模块的 renderer 不在 `Plugin.php` 里，而在 `src/UserFiles/Admin/Page::register_renderers()`（挂 `init`、优先级 20）。
3. **`Layout::PAGES`**：加一条 `'页面id' => array( 'order' => array(...), 'cards' => array( 卡片id => array( 行, 列, 跨列 ) ) )`，12 列网格、行列 1-based。**漏了不报错，卡片会退化成组件默认宽度**（非 wide 卡直接交给 CSS 自动放置，wide 卡占满一行）。
4. **`Layout::layout_for_page()`**：只有当页面 id 与布局 id 不同时才需要补别名（现有 9 条：`image-rules → image`、`image-thumb → thumb`、`image-backup → backup`、`storage-connection → s3`、`storage-sync → sync`、`storage-deletes → deletes`、`storage-rewrite → rewrite`、`storage-cost → cost`、`files-zibll → files-space`）。

### 6.2 岛本体：五处

5. **payload**：新建 `src/Admin/{Page}_Payload.php`（文件空间的在 `src/UserFiles/Admin/`，子比增强的在 `src/Zibll/`），`build()` 返回 `page` / `head` / `cards` / `config` 四块。
   - `page` 直接交给 `UI::page()`，要带 `'island' => true` 与 `'skeleton' => array( 'kpis' => N, 'kpi' => 高, 'cards' => array( 卡片 id… ) )`：前者让 `Page::render()` 打上 `data-sakura-island` 并输出首帧标记，后者画骨架（高度查 `UI\Page::boot_height()`，新增卡片要补一行）。
   - `head` 用 `UI\Page::head_data( $page )`，不要另拼一份。
   - `cards` 每张卡带 `id` / `title` / `description` / `placement`；`placement` 必须取自 `Layout::card( Layout::layout_for_page( $page ), $card )`，格式是 `array( 行, 列, 跨列 )` **三元数组**——共享 `Card` 用 `const [row, col, span] = card.placement` 解构，传对象会白屏，控制台只有一条 TypeError。
   - 文案全部进 `config.strings`，由 `*_Payload::strings()` 用 `__()` 生成。
6. **React 源**：`assets/ui/src/{页面}/index.jsx` 负责挂载与失败兜底，`app.jsx` 是外壳，其余文件按页签或部件分；跨页共用的件放 `assets/ui/src/shared/ui.jsx`。目录约定见 [12-React代码规范.md](12-React代码规范.md) §2。
7. **bundle**：`npm run build`（= `node bin/build-ui.mjs`）把每个含 `index.jsx` 的目录打成一个 `assets/ui/dist/{name}.js`。**产物必须提交**——发布包用 `git archive` 只取已跟踪文件，没提交的 bundle 在站点上等于不存在，页面会永远停在骨架屏。
8. **挂载视图**：新建 `includes/views/{page}-island.php`，在挂载节点**之外**打印 bootstrap JSON，再用 `UI::page()` 开一个空 body：

   ```php
   <?php
   /** @var array<string,mixed> $payload */
   if ( ! defined( 'ABSPATH' ) ) { exit; }
   if ( ! current_user_can( 'manage_options' ) ) { return; }

   echo '<script type="application/json" id="sakura-my-bootstrap">';
   echo wp_json_encode( $payload, JSON_HEX_TAG | JSON_HEX_AMP | JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES );
   echo '</script>';

   UI::page( $payload['page'], static function (): void {
       // 空 body：Page::render() 已打印顶栏、页头与首帧标记，React 挂载后替换 <main> 的子节点。
   } );
   ```

   bootstrap 的 `id` 要和 `index.jsx` 的 `getElementById()` 对齐（约定 `sakura-{name}-bootstrap`），脚本标签必须在 `UI::page()` 之前——写在里面会被挂载覆盖。
9. **入队 + 登记**：① 在页面模块的 `enqueue_*()` 里 `wp_enqueue_script( …, SAKURA_TOOLS_URL . $bundle, array( 'sakura-admin-core' ), Page_Assets::asset_version( $bundle ), true )`；② 在 `Page_Assets::ISLAND_BUNDLES` 加一行 `'页面id' => $bundle`。第 ② 步同时是「停用旧页脚本」的开关（`island_owns()`），漏了就是两个渲染器同时绑 DOM——点一次按钮发两次请求。

### 6.3 回退规则：bundle 不可读时回到旧页

`Page_Assets::island_owns( $page )` 的判据只有两条：`ISLAND_BUNDLES` 里有这一页、它的 bundle 在磁盘上可读。岛上线之后，回退路径必须一直能用：

| 情况 | 渲染 | 旧页脚本 |
|---|---|---|
| 表里有该页、bundle 可读 | payload + `{page}-island.php`（岛） | **不入队** |
| 表里有该页、bundle 不可读 | 旧视图（`includes/views/{page}.php` 等） | 入队 `assets/ui/js/pages/{page}.js` |
| 表里没有该页（如 `system-settings`） | 按模块自己的逻辑；系统设置没有旧视图，永远走岛 | 有就入队 |

- 旧视图还在的页（图像优化四页、对象存储五页、文件空间设置页与三个列表页）回退到经典表单，保存仍走 `options.php` / `admin-post.php`；
- 旧视图已删的**纯岛页**（`files-zibll`、`zibll-performance`）没有旧表单：渲染器要显示「资源缺失」提示，不能让 `require` 直接 fatal（照 `Space_Page::render_missing_bundle_notice()` 与 `Zibll\Admin_Module::render_missing_bundle_notice()` 写）；
- `system-settings` 是历史例外：不在 `ISLAND_BUNDLES` 里，由 `System_Settings_Module::enqueue_admin_assets()` 自己入队 `system.js`，也没有旧视图；改它时别照抄「回退」假设。

渲染方法的第一行永远是权限守卫，然后才决定走岛还是回退：

```php
public function render_mytab(): void {
    if ( ! current_user_can( 'manage_options' ) ) {
        return;
    }

    $bundle = Page_Assets::island_bundle( 'image-mytab' );

    if ( '' !== $bundle && is_readable( SAKURA_TOOLS_PATH . $bundle ) ) {
        $payload = ( new My_Payload() )->build();
        require SAKURA_TOOLS_INC . 'views/image-mytab-island.php';
        return;
    }

    $data = $this->service->collect();
    require SAKURA_TOOLS_INC . 'views/image-mytab.php';
}
```

`Menu::render()` 已经查过一遍能力，但**视图自己再查一次**是现有惯例——renderer 也可能被别处直接调用；岛挂载视图里同样要再查一次。

### 6.4 回退视图的写法（只在 bundle 缺失时跑到）

```php
<?php
/**
 * @var array<string,mixed> $data
 */
use Sakura\ImageOptimizer\Admin\UI;

if ( ! defined( 'ABSPATH' ) ) exit;
if ( ! current_user_can( 'manage_options' ) ) return;
?>
<?php UI::page( array( 'id' => 'image-mytab', 'module' => 'image', 'tab' => 'mytab', 'title' => __( '我的页面', 'sakura-imgopt' ) ), function () use ( $data ): void { ?>
    <?php UI::card( array( 'id' => 'my-card', 'title' => __( '设置', 'sakura-imgopt' ) ), function () use ( $data ): void { ?>
        ...
    <?php } ); ?>
<?php } ); ?>
```

要点：

- 顶部 PHPDoc 用 `@var` 逐条声明模板变量（PHPStan 靠它推断类型）；
- `ABSPATH` 守卫 + 能力守卫，一个都不能少；
- 变量在模块里算好再 `require`，模板里不做查询；
- **回退视图也要验收**：`mv assets/ui/dist/image.js /tmp` 后打开该页，表单能显示、能保存、能弹提示；验收完把 bundle 放回去。

## 7. 常量、钩子、option 的命名

| 对象 | 前缀 | 例子 |
|---|---|---|
| option | `sakura_imgopt_` | `sakura_imgopt_quality` |
| UserFiles option | `sufm_` | `sufm_settings` |
| cron 钩子 | `sakura_imgopt_` | `sakura_imgopt_s3_delete_tick` |
| AJAX action | `sakura_` | `wp_ajax_sakura_s3_sync_scan` |
| 表名 | `{prefix}sio_sync_` / `{prefix}sufm_` / `sio_s3_*` | 见 04 |
| REST 命名空间 | `sufm/v1` | — |
| CSS 类 | `sakura-` 或不加前缀的组件类 | `.sakura-admin`、`.card` |
| JS 全局 | `SakuraAdmin` / `window.sakuraPage` | — |
| bootstrap JSON id | `sakura-` | `sakura-image-bootstrap`、`sakura-files-admin-bootstrap` |

PHPCS 的 `WordPress.NamingConventions.PrefixAllGlobals` 白名单是 `sakura_imgopt`、`sakura_tools`、`sufm`、`sakura`、`Nboke`。**用了别的前缀会直接报错**。

翻译域只有一个：`sakura-imgopt`。

## 8. 文案与国际化

- 所有面向用户的字符串走 `__()` / `esc_html__()` / `esc_attr__()`，域固定 `sakura-imgopt`；
- **JS 里不写裸中文**：岛页把文案塞进 payload 的 `config.strings`（`*_Payload::strings()` 用 `__()` 生成），React 只读 `boot.config.strings`；只有回退页的旧脚本读 `Page_Assets::set_data()` 写进 `SakuraAdmin.data` / `sakuraPage`。同步中心还有一批 JSX 里硬编码的中文待迁，清单在 [12-React代码规范.md](12-React代码规范.md) §11.1；
- `data-label` 之类的 HTML 属性**不走翻译**（`__()` 在属性里会被 PHPCS 判为未转义），要放在 `data` 里传；
- 中文与英文混排时，数字与单位之间不加空格，术语沿用现有译法（「媒体库」「对象存储」「缩略图」）。

## 9. 写测试

每加一类新逻辑，至少配一个测试文件：

| 改动 | 测试放在 |
|---|---|
| 纯服务类 | `tests/XxxTest.php` |
| 后台渲染 | `tests/Admin/` |

## 12. 新增 S3 存储厂商（存储桶）

> **先做稳，再谈兼容。** 接入一家 S3 兼容存储时，验收标准是「能连、能传、能删、能回显、失败不丢文件」；ACL 与 ETag 只作为兜底，不做成产品卖点。

这里的「新增存储桶」指在连接页增加一个可选 `provider`，并让它跑通从连接到删除的完整链路。**只加一个下拉标签不算接入**，也不能拿 mock 单测代替真实桶验收。

### 12.1 五条链路，缺一不可

| 链路 | 必须实际验证 | 常见失败 |
|---|---|---|
| 能连 | 用真实账号、真实桶点「测试连接」，能区分 DNS/TLS、403、404、region、bucket 不存在 | endpoint 写成控制台/API 地址；path-style 与 virtual-host 选错 |
| 能传 | 小文件走单段 PUT，默认 ≥16 MiB（`sakura_imgopt_multipart_threshold`）走分片；上传后对象可读、Content-Type 正确 | 分片 ETag 格式不同；ACL 头被拒；同一桶小文件成功、大文件失败 |
| 能删 | 单条删除、批量删除队列、远端已不存在时幂等成功 | 403；批量里一条失败拖垮整批 |
| 能回显 | 媒体库缩略图、文章图片、特色图、改写后的 URL 都能加载（含自定义域名/CDN） | 自定义域名未绑定/未缓存；URL 改写后仍指向旧域名 |
| 失败不丢文件 | 上传失败保留本地文件与已上传对象；不静默删本地；错误可见；删除失败留在队列重试 | 先删本地再传；失败后对象遗留但无记录 |

**未通过五条链路前，不要放进 `Providers::selectable()`。** 可以留在 `Providers::all()` / `Providers::exists()` 里让旧档案继续打开，但新建下拉不出现——七牛、百度、又拍目前就是这样处理的。

验收必须在真实桶上完成，并在交付说明里写清 endpoint、bucket、测试文件大小，以及删除和回显的结果。单测只能证明分支，不能证明厂商兼容。

### 12.2 ACL 与 ETag 的边界

- **对象 ACL 不作为主选项。** 当前连接页不暴露 `object_acl`；它只作为旧档案/旧行为的兼容值保留。未来若确需暴露，只能作为默认折叠的高级兼容项，不承诺「支持 ACL」，也不作为新厂商的接入门槛。匿名访问由存储空间策略与 CDN 决定，不由对象 ACL 决定。
- **ETag 只做上传后的完整性兜底。** 单段与分片的 ETag 语义不同，厂商还可能返回非 MD5 值；校验不通过时应保留对象与本地文件并明确报错，不能静默成功。厂商不返回标准 ETag 时，按能力降级为告警或跳过校验，不要让主链路失败。
- **不要把 ACL/ETag 做成卖点或必填项。** 兼容处理应内部化；不要为了迁就某家厂商的 ACL/ETag，反过来要求「能传、能删」为它让路。

### 12.3 落点清单

1. `src/S3/Providers.php`：`all()` 加标识与标签，`selectable()` 只收已验收的厂商，`hidden()` / `exists()` 同步。`exists()` 只比较标识、不生成标签，避免在 `plugins_loaded` 阶段加载文本域。
2. `src/S3/Client_Factory.php`：确认 `VIRTUAL_HOST_PROVIDERS` 与 `path_style_for()`；需要临时凭据或特殊签名的厂商（如多吉云）在 `make()` 里单独分支。**分支只负责把 `credentials` 装成一个 callable 交给 SDK，不要在构造期去取凭据**——临时凭据的有效期可能短于一次批量任务，取一次用到底必然在中途失效。工厂里已定的两条硬约束见 `07-S3存储生命周期.md` 的 R17：闭包必须返回 Promise（`Create::promiseFor()` / `Create::rejectionFor()`），且 `new Credentials()` 必须带第四个参数 `$expires`（不传就会被当成永久凭据，永不续期）。新厂商的凭据失败请抛 `src/S3/S3_Credential_Error.php`，并在「用户在等结论」的入口（连接测试、探测、同步中心测试）调一次 `Client_Factory::preflight()`，否则失败会被 `Connection_Probe` 报成「Endpoint 没有响应」。
3. 连接页要补两处：`src/Admin/Storage_Payload.php`（厂商的 endpoint / region / bucket 提示、默认值与「只对某厂商显示」的字段开关，现有 `$provider_hints` 表就在这里）与 `assets/ui/src/storage/connection.jsx`（渲染、自动填充与显隐）；bundle 缺失时回退到 `assets/ui/js/pages/storage-connection.js`，回退页不再承载新厂商的专属逻辑，但同一份提示文案要能对上。
4. 测试：`tests/S3ProvidersTest.php`、`tests/S3ClientFactoryTest.php` 至少覆盖「可选/隐藏/exists」与 path-style 判断。
5. 文案：连接页写清该厂商的 endpoint 格式；没有实测过的兼容性，不要写成「支持」。
