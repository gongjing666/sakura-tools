# 03 后台 UI

> 本页是 [开发规则](00-索引.md) 的第 3 篇。改后台样式、加卡片、加页签、调布局之前先读一遍；第 12 节的验收清单是提交前的硬门槛。

适用范围：图片优化（`sakura-tools-image`）4 页、对象存储（`sakura-tools-storage`）3 页、文件空间（`sakura-tools-files`）5 页、系统设置（`sakura-tools`）与批量处理页。后台只有一套样式栈，全部页面加载 `assets/ui/`；旧的 `admin*.css`、`admin.js`、`admin-layout.js`、`userfiles-admin.*`、`userfiles-space-admin.*` 已删除，不要再引用，也不要新造第二套皮肤。

## 1. 样式分层与加载顺序

`src/Admin/Page_Assets.php` 按以下顺序加载：

1. `assets/ui/tokens.css`：设计令牌，只有 `:root`。
2. `assets/ui/base.css`：画布、共享顶栏、模块切换、页签、页头、通用排版与 WP 管理页槽位重置。
3. `assets/ui/components.css`：卡片、表单、按钮、状态、保存条、弹窗（含全局提示弹窗 `.sakura-modal`）、表格、提示等组件。
4. 卡片列宽不单独加载样式：`UI::card()` 按 `Layout::PAGES` 把位置写成行内**自定义属性** `--g-card-row` / `--g-card-col` / `--g-card-span`，由 `components.css` 的 `.card-grid > .card` 换算成 `grid-row` / `grid-column`。走变量而不是直接写 grid 坐标，是为了让内联优先级不压过移动端媒体查询（当初写死坐标时，≤1100px 的单列规则失效，卡片被挤成 1/12 屏宽）。
5. `assets/ui/pages/{module}.css`：模块级样式；模块名取页面 id 的第一段，例如 `image-rules` → `image.css`。
6. `assets/ui/pages/{page}.css`：单个页面的补充样式，只在文件存在时加载。

脚本顺序固定为 `core.js` → `api.js` → `ui.js` → `pages/{page}.js`。**没有布局脚本**：卡片位置在服务端就确定，首帧即最终形态。

规则：

- 视觉修改只写 `assets/ui/`。页面专属样式优先复用 `components.css`；确属一次性的少量规则，先放模块 stylesheet，超过约 50 行再拆 `pages/{page}.css`。
- 配色是「樱雾」一套：暖樱白画布 + 白卡片 + 深樱强调色。允许粉色，但只允许 `tokens.css` 里这一组樱色（`--g-sakura-1..4` 与 `--sakura-*`）；不要在页面里另调一个粉或另调一个红，也不要用天蓝色。
- 图片与插画：禁止照片、外链图、位图背景。几何 SVG（花瓣、印章、小鲸鱼）允许，但必须来自 `assets/ui/icons/` 并在 PHP 里内联，见 §14.7；画布由 `base.css` 的三层径向渐变 + 一条线性渐变生成；原先那层「花瓣微尘」点阵（`.sakura-admin::before` 的 7 个椭圆斑点）已于 2026-11-19 移除——它在 1440 下被读成脏点，且与 V2 的纯色渐变画布冲突。
- 唯一强调色是 `--g-accent`（V2 起为 `#C7335B`，白字 5.18:1，见 §14.2）；状态色只表达状态。品牌粉 `#FF8FB8` / `#E4577F` 只能做装饰与渐变，永远不承载文字。
- 不要用 `!important`。若确需覆盖 WordPress 管理页槽位（`#wpcontent` / `#wpbody-content`），先用 `:has(.sakura-admin)` 限定作用域，再在评审中说明原因。
- 页面根节点由 `UI::page()` 输出 `.sakura-admin[data-sakura-page]`。不要再手写 `.sakura-sync-app`、`.sky-layer`、`.sakura-layer`、`.app` 这些旧根节点。
- **唯一的全后台资源**是 `assets/ui/admin-menu-icon.css`：它由 `Admin\Menu::enqueue_menu_icon()` 挂 `admin_enqueue_scripts` 无条件加载，只负责左侧菜单的项目图标（`#toplevel_page_sakura-tools`）。菜单注册时第 6 个参数传 `'none'`，WordPress 会留空 `.wp-menu-image` 且不加 `menu-icon-generic`，我们再用 `mask-image: url(icons/sakura-mark.svg)` + `background-color: currentColor` 画上去——mask 不是图片，所以图标自动跟随菜单静止/悬停/当前项三态配色，也能适配 8 套后台配色方案。**这是本节表格之外唯一允许的后台样式文件**；新增第二份全后台 CSS 前先问：它是不是可以并进这个文件或 `base.css`。
- WordPress 媒体库的样式独立放在 `assets/ui/wp-media/`，由 `Media_Hooks` 按屏幕单独加载，不属于后台页面布局，不参与上表顺序：`media-library.css` 只加载于 `upload.php`；`media-modal-folders.css` 在除 `upload.php` / `media-new.php` 外的后台屏幕加载（媒体弹窗可从任意页面打开，因此后台页面上看到它是正常现象）；`media-new-folders.css` 只加载于 `media-new.php`。

## 3. 间距：自适应但有下限

所有横向内边距用令牌，不写死：

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--g-gutter` | `clamp(16px, 2.4vw, 30px)` | 页面左右留白 |
| `--g-app-top` | `clamp(14px, 1.7vw, 22px)` | 页面顶部留白 |
| `--g-app-bottom` | `clamp(56px, 5vw, 80px)` | 页面底部留白 |
| `--g-page-max` | 1480px（系统设置可设 960–1920px） | 内容最大宽度 |
| `--g-card-pad-x` | `clamp(17px, 2.1vw, 24px)` | 卡片左右内边距 |
| `--g-card-pad-top` | `clamp(18px, 1.9vw, 22px)` | 卡片顶部 |
| `--g-card-pad-bottom` | `clamp(18px, 2vw, 24px)` | 卡片底部 |
| `--g-stack` | `clamp(16px, 1.6vw, 20px)` | 页头与内容之间、页内顶层区块之间的堆叠 |
| `--g-grid-gap-x` / `--g-grid-gap-y` | 20px（系统页可设 0–48px） | 桌面多列卡片网格的左右 / 上下间隔 |
| `--g-space-1` … `--g-space-6` | 6 / 10 / 14 / 18 / 24 / 32px | 组件内部节奏 |

硬性下限：

- 文字到卡片边框至少 16px；嵌套面板内至少 12px。
- 相邻卡片之间至少 16px；卡片网格读取系统设置页「布局设置」保存的 `Layout::gaps()`，由 `Page_Assets` 写成 `.sakura-admin` 的 `--g-grid-gap-x` / `--g-grid-gap-y` 行内变量。
- 同一条竖直内容线：卡片标题/正文、KPI、页头状态卡、页面级面板都使用 `--g-card-pad-x`；只有卡片内部的嵌套框降一级。
- 不允许再引入 13/15/17/19px 这类一次性内边距；嵌套框统一用 `--g-space-3`，行内上下用 `--g-space-2`，紧凑网格用 `--g-space-2`。
- 页面上下留白用 `--g-app-top` / `--g-app-bottom`，不要在断点里写死 18/20/60。
- 页面不允许横向滚动（`scrollWidth == innerWidth`）。表格放不下时只能让 `.table-wrap` 内部横向滚动。
- `.page-body` 的直接子块（KPI 行、卡片网格、独立卡片）统一由 `base.css` 的 `.sakura-admin .page-body > :not(:first-child) { margin-top: var(--g-stack); }` 拉开。`:not(:first-child)` 的特异性是故意的，用来压过 `components.css` 后面 `.card { margin: 0 }` 的复位；不要改回 `* + *`，否则独立卡片又会和上一块贴在一起。验收时相邻块间距桌面 20px、窄屏 16px，不能出现 0。
- KPI 网格自身也用 `--g-stack` 作 `gap`；不要在单页 CSS 再给 `.kpis` 加 `margin-bottom`，否则会与上面的堆叠叠加成双倍。
- 自适应是重排，不是按设备写死。除极窄屏（≤360px）外，不要为某个机型单独写断点；这个断点只允许给确实放不下的控件做紧凑化。

## 4. 边框与层级

- 一张卡片只有一层可见边框：`var(--g-card-border-width, 1px) solid var(--g-line)` + `var(--g-radius-card)` 圆角 + `var(--g-shadow-card)`。默认是 1px / 18px / 三层柔和阴影；系统设置可以整体改细、改圆或去掉阴影，但不要在同一页对单张卡片另写一套。
- 卡片内部的分组用分隔线（`--g-line-soft`），不要再套一张带边框的卡。
- 表单行在移动端是「分隔线分隔的块」，不是第二张卡。
- 嵌套结构（缩略图尺寸表、开关列表）只保留最外层一个框，内部用 `border-top` 分隔。
- 阴影只表达层级，不表达状态；hover 不额外加边。
- 选中态不用黑色内描边。已保存配置卡有两种选中态：**正在使用的**（`.profile-card.is-active`）用樱花粉渐变 `linear-gradient(145deg, #FFC6DB 0%, #FFAACA 46%, #FF8FB8 100%)`（与顶栏品牌瓦片同一套色阶梯）+ 墨字（`--g-ink`，8.07–6.72:1），说明文字换 `--g-ink-soft`（6.38–5.32:1——`--g-muted` 在整条渐变上只有 3.08–3.69:1，不达标；警告用 `#8A2F22` 4.72:1），badge 用白底压 `--g-accent-hover`（6.94:1），**整条渐变上都不能放白字**（1.5–2.13:1，读不出来）；**只是被选中的**（`.profile-card.is-current`）用 `--g-accent-soft` 浅樱实底（这一档保持平的，好和上面对比出「浓＝在用／淡＝存着」）。渐变的两端与 `--g-paper` 亮度接近，靠 `inset 0 0 0 1px rgba(199, 51, 91, .22)` 这圈彩色内描边把边界立住（不是黑描边）。键盘焦点用 `--g-select-focus` 2px 外环，粉底上换成 `--g-ink` 外环；普通鼠标点击不显示焦点环（`.profile-card:focus { outline: 0 }`，只有 `:focus-visible` 才画环）。
- 已保存配置卡底部的动作（`.profile-item__actions`）是等分两列网格，`连接测试` 在前、`删除此配置` 在后，各占一半且文字居中，卡片左右两边都不留空档。两个按钮共用一套「柔和」底子：**白纸底 `--g-card` + 一根彩色细边 + 文字自己扛对比度，不填实心、不带投影**——实心块会和上方樱花粉卡片抢注意力。测试按钮中性（`--g-line-strong` 框 + `--g-ink-soft` 字，11.3:1），hover 才染粉（`--g-accent-soft` 底 + `--g-accent-hover` 字 5.77:1；用 `--g-accent` 只有 4.31:1，落在 4.5 线下面）；删除按钮静止态就是「红细边 + 红字」（`--g-bad` 压白底 6.44:1），hover 才铺 `--g-bad-bg` 底；禁用时红色全撤、边框改虚线、`--g-wash` 底 + `--g-muted` 字（6.33:1）。不要用 `.btn--quiet`——透明底加 muted 文字读起来像说明文字而不是控件。测试按钮必须是删除表单的兄弟节点而不是 `<button type="submit">`，否则点测试会提交删除。
- 子比主题在 `admin-main.min.css` 里有一条全局 `[disabled] { opacity: .6 !important }`。禁用态若要露出可读的原因文案（如「使用中不可删除」），必须写 `opacity: 1 !important` 覆盖，否则 muted 文字会掉到 3:1 以下。
- 「选择器 + 该选择器的已存项」放同一行时（对象存储的「服务商」下拉与其已保存配置 chip），用两列网格承载两半，各自内部是「标签 → 控件」的竖排，两边标签同字号同粗细、标签下间距一致，控件才会落在同一条基线上。chip 固定 `height: var(--g-ctl-h)` 单行显示，才能和 38px 的下拉框等高；换成两行堆叠的 chip 会让这一行失去基线。
- 同一行里右侧是可变长列表时，**不要给列表加 `max-height` + 内部滚动**。这类 chip 往往是进入某项编辑的唯一入口，藏在滚动条后等于让人找不到；让它自然换行，行高由内容决定，左侧控件靠 `align-items: start` 钉在首行即可。
- 宽度断点里改 `grid-template-columns` 的媒体查询必须写在这条规则**之后**：同特异度下后写的赢，写在前面的媒体查询会被基础规则整体覆盖，表现成「窄屏下选择框溢出自己的单元格」。

### 4.1 卡片动作与保存

- **一张可编辑卡片 = 一个独立表单，只保存本卡。** 用 `UI::card( array( 'form' => array( ... ), 'save' => '保存设置' ), $body )`，组件会把 `form` 放进 `.card__body`，字段和保存条都在同一个表单内；不要把 `section` 本身换成 `form`，也不要在视图里手写 nonce。
- 多 option 表单传 `form.option_group`，由组件输出 `option_page` / `action=update` / `_wpnonce`；字段标记用默认的 `markers=fields`（等同 `Card_Form::fields( $card )`）。单个数组 option 用 `markers=option_fields` + `option`，把 `_sakura_card` 写进该 option 数组。自定义 saver 用 `markers=none` 并在视图里自行输出 nonce。
- 服务端必须按卡片合并已存值：`options.php` 多 option 用 `Card_Form::guard_options()` 保护未提交字段；单数组 option / 自定义 saver 按卡片标记只更新本卡字段。未提交字段保持原值，未知卡片直接返回旧值，不能清空。
- checkbox 组要有 hidden `0`；保存本卡时未勾选必须能写回 0。
- 保存按钮由组件输出在 `.card__savebar`，靠右；移动端按钮整宽。按钮文案说明保存范围（如「保存为新配置」「保存清理策略」），单卡内可统一写「保存设置」。
- 只读卡、纯操作卡（清理、探测、刷新、删除队列）不传 `form` / `save`，动作按钮留在卡内的 `.card__actions` 或 `.card__savebar`，不要再造页面级操作条。卡头按钮用 `actions`：链接传 `label` + `url`；需要 JS 绑定的普通按钮传 `label` + `button => true`，可再传 `id` / `attrs` / `variant` / `disabled`。有 `kicker` 时 `.card__actions` 会自动下沉 20px，让按钮顶边与标题首行齐平。
- 卡头动作最多三个；超过三个先合并或移到卡内。≤782px 时 `.card__head` 允许换行，`.card__actions` 自动落到标题下方、整行右对齐并允许按钮换行，不能把标题挤成一条细缝，也不能横向溢出。
- 以「行/项」为保存单位的列表卡（如用户容量）把保存按钮放在对应行内，这是唯一例外。
- 不再使用整页 `.page-savebar`，也不再使用浮动保存条。新增页面直接照本节写，不要回到「多卡共享一个表单、按钮提交整组」的旧模式。
- **原地保存（2026-11-23 起，默认目标）**：`form` 里加 `'inplace' => true`，`Card::form_open()` 会输出 `data-sakura-inplace="1"`，`ui.js` 的 `initInPlaceSaves()` 把这次提交改成 `fetch`，不再整页 POST + 302。服务端一点没变：还是同一个 `options.php`、同一份 nonce、同一套 `guard_options()`。拿回整页 HTML 之后只抄三样东西——根节点行内样式与 head 里的 inline style 块（页面宽度、卡片圆角、卡片间隔当场生效）、服务端**实际保存**的控件值（`sanitize()` 会 clamp：输入 3000 宽回写 1920，界面必须跟着回写）、这次保存的提示弹窗（就是服务端渲染的那一份，去掉 `autoshow` 后由 `openModal()` 打开）。于是保存不重载、不滚动、不重播 `<main>` 的 180ms 进场，也就没有「先到页顶再跳回来」。
- 只有**保存结果不影响同页其它卡片的读数**时才开 `inplace`。这条路径不重画任何节点：页面脚本是直接绑在节点上的（`storage-*`、`files-*`），换节点会让它们变聋；别处渲染的派生值（对象存储绑定状态、成本估算、重写规则预览）不会更新。那种卡继续走整页提交。
- 回退是显式设计：fetch 失败、返回的不是本插件的页、或重定向到了别的 `page=`，`ui.js` 会放开按钮并让浏览器照常提交——`sessionStorage` 里那份滚动记录此时还在，重载后仍会恢复。

### 4.2 布局与外观设置

- 系统设置页「布局设置」卡同时保存卡片间隔与全局外观，写入 `sakura_imgopt_layout_gaps` 和 `sakura_imgopt_ui_style` 两个 option。这张卡开了 `form.inplace`（见 §4.1），**保存后当场生效、不刷新页面**。
- 可调项与范围：页面宽度 960–1920px（默认 1480）、边框粗细 0–6px、圆角 0–40px、阴影 默认/无/轻/强。**页面背景色与卡片背景色已于 2026-11-19 从系统设置移除**（V2 决策）：分层樱雾与和纸卡片是整套视觉的地基，允许自定义底色会同时打破对比度保证与纸感，且与 V2 的渐变画布互相打架。
- 外观值由 `Appearance::inline_style()` 只在非默认时输出到 `.sakura-admin` 根节点：`--g-page-max`、`--g-card-border-width`、`--g-radius-card`、`--g-shadow-card`。默认状态下不输出行内样式，令牌表保持唯一来源；`Appearance::DEFAULTS` 也不再含 `page_bg` / `card_bg`，旧站点保存过的这两个键会被 `sanitize()` 丢弃，不会再覆盖令牌。
- 卡片背景只改 `--g-card-surface`；`--g-card` 继续给输入框、按钮、下拉使用，否则卡片一换色，控件也会跟着变色。页面背景换成深色时要检查正文对比度，系统设置里已有提示，不能为了「个性」牺牲可读性。

### 4.3 表格与分组

- 一张表只允许一个 `<thead>`。不要把同一组数据 `array_chunk()` 成两张表各自带表头；等级加成曾因此出现两遍「等级 / 门槛积分 / 加成（MB）」。
- 需要分栏或分组时，用单表 + 分组行，或两个不带 `<thead>` 的面板并排；只有打印或固定表头场景才重复表头，且必须是有意为之。

### 4.4 列表页筛选与操作

- 列表页的状态计数只保留一层：删除队列把「排队 / 执行中 / 失败 / 已放弃」做成列表卡内的四个紧凑状态块，不要再在卡片上方放一排同义的大 KPI，也不要再放一个重复的「全部状态」下拉；页面级只保留右上角状态卡。四个状态块占满卡内工具行，再次点击当前状态回到全部。
- 列表卡的工具行负责筛选，不再承担主操作。主操作（重新核对、导出、补建）放卡头 `actions`，与标题同排；筛选行的搜索框 240px（上限 280px）、下拉 160px（上限 180px），控件用 `flex:0 0 auto` / `flex:0 1 240px`，禁止 `flex:1` 或 `width:100%` 拉满；保持一条，≤782px 再换行。宽度上限见 10.2。
- 状态块使用 `aria-current="true"` 表示当前筛选；再次点击当前状态回到全部，不另设同义下拉。若页面还有其他筛选下拉，必须与状态块同步（同一 `state` 参数）。
- 卡头已经有三个按钮时（用户容量：重置容量 / 同步容量 / 刷新），搜索框不要挤成卡头第四个控件；它留在卡内工具行、左对齐 240px，≤782px 才整行。搜索框不是按钮，但也不靠“它是筛选”这个理由破例。
- 列多的用户容量表按生产版固定列宽：用户 28%、容量使用 34%、文件 90px、单独容量 210px，`table-layout: fixed`；最后一列表头与内容右对齐，输入框和保存按钮靠右。≤1100px 收窄为 26% / 32% / 76px / 192px，≤782px 必须恢复 `table-layout: auto` 与 `width: auto`，否则窄屏会内滚。表内多段文字用两条 `.files-cell__line`，不要让三段竖排把行高顶到 84px。

## 5. 页头、状态与弹窗

- 页头由 `UI::page()` 输出：上方眉标（`.page-head__eyebrow`）、标题、1–2 行说明（`.page-head__lede`），说明下方是可选的页头操作（`.page-head__actions`，靠左，与说明间距 20px）；状态卡单独放右侧，不与操作按钮同排。页头底部一条 `--g-line` 分隔线。不要放樱花插画、照片或高对比大面积色块；樱色只出现在画布、卡片泛光、按钮和图表里。
- 背景默认是暖樱白底 + 3 层樱雾径向渐变 + `.sakura-admin::before` 的点阵「樱尘」（`base.css:33-79`）；系统设置可以换成单一纯色，但默认值必须保持这套樱雾画布，禁止贴图。改画布只改 `tokens.css` 的 `--sakura-*` 与 `base.css` 的这几层渐变，不要往页面里塞背景图。
- 卡片表面是 `--g-card-surface` 打底 + `--g-card-bloom` 叠一层角落泛光（`components.css` 的 `.card`）。改卡片颜色时颜色和泛光要分开写：`background-color` 放令牌，`background-image` 放泛光，否则系统设置里的自定义卡片色会被盖掉。
- 顶栏状态胶囊支持 `ok / off / warn / error`：未传 tone 时是中性灰点；`ok` 绿点，`off` 灰字，`warn` 琥珀，`error` 淡红。不要所有状态都用绿点。
- 页头状态卡与页头内的小状态标签同样遵循语义，不要用绿色表示「等待配置」。

### 5.1 提示弹窗（`.sakura-modal`）—— 全局组件

**两条通道，别混用：**

| 场景 | 用什么 | 例子 |
| --- | --- | --- |
| **动作结果**（用户刚点了按钮） | 居中提示弹窗 `UI::modal()` | 保存成功/失败、连接测试结果、重置统计、批量重排、投递测试 |
| **持续状态**（明天还在） | 页内 `UI::alert()` / `UI::notice()` | 对象存储已停用、兼容模式、密钥无法解密、主题不是子比、待处理差异 |
| **AJAX 小动作**（不离开当前页） | 右下角 toast `admin.ui.toast()` | 复制成功、异步刷新失败、指标刷新 |

判断标准只有一句：**这个提示是「刚刚发生的一件事」还是「现在的一个状态」**。前者弹窗，后者页内。不要两者都来一遍——同一个事实不允许「顶部 notice + 弹窗」重复出现。

不允许再用 WordPress 原生 `notice notice-*` 输出（`admin_notices` 钩子也一样）：跨页面的维护类提示走 `\Sakura\ImageOptimizer\Admin\UI\Feedback::admin_notice_html( $message, $tone, $link, $label )`，它自己带一个 `.sakura-admin-notice-root` 外壳，样式与页内 `.alert` 同源。

**跨页 notice 必须自带样式栈。** `admin_notices` 在媒体库、仪表盘、用户列表这些**不是插件页面**的屏幕上也会触发，而那些屏幕不会加载 `assets/ui/`，`admin_notice_html()` 在那里会渲染成无样式裸文本，看起来又变回「原生提示」。所以凡是可能出现在任意后台屏的 notice，都要在 `admin_enqueue_scripts`（优先级 99）里按「这条提示会不会渲染」决定性条件调 `Page_Assets::enqueue_notice_style()`——它只入队 `tokens.css` + `components.css`，**故意不含** `base.css`（那里是整页画布，不能进别人的页面）。现有两个消费者：`S3\Storage::enqueue_notice_assets()`（失败/补删/漂移提示）与 `Zibll\Notices::enqueue_style()`（主题能力提示）。

- **样式在 `components.css` 的「Prompt modal」段**（全局，没有页面前缀），结构由两处输出：
  - `src/Admin/UI/Modal.php` + `UI::modal( $args )` / `UI::modal_html( $args )` —— 保存结果、检测结果、任何一次性事件都用它。`$args`：`id`、`tone`（ok/bad/warn/info/neutral，决定图标配色）、`kicker`、`title`、`message`、`body`、`size`（`compact` = 440px，报告类用；省略 = 560px）、`button`、`variant`、`autoshow`、`return_to`。
  - `src/S3/Config_Notice.php` —— 对象存储的三条**拦截式**提示（配置缺失 / 已停用 / 未核对），自带「不再提醒」与主按钮，用的是同一套类名。对象存储的缺失项胶囊样式仍在 `storage.css`（`.sakura-config-missing` 等），那是页面专属家具。
- **图标五色**：`--ok` 绿、`--bad` 赤、`--warn` 琥珀、`--info` 灰紫、`--neutral` 暖灰。成功不要用主按钮的樱红，否则和「失败」分不开。
- **弹窗不得改变用户的位置**（新窗口、关闭都一样）。这条是硬性的，验收时按下面三项量：
   - **滚动位置**：打开前 `scrollY` 是多少，关闭后必须还是多少，误差 0；弹窗内部滚动不继承给页面。**不锁滚动**：不钉 body、不设 `html { overflow: hidden }`，滚轮照旧滚页面——「锁 → 跳 → 解锁 → 再跳」正是旧实现的抖动来源。提示弹窗自 2026-11-20 起**有一层遮罩**（`--g-overlay` 色调 + `backdrop-filter: blur(3px)`，点遮罩关闭、拦截指针），所以弹窗打开时页面点不动，但位置不能因此改变：遮罩只渐变透明度，不位移、不改文档高度。
  - **焦点位置**：打开时焦点落标题、关闭时回到触发元素，但**两次焦点都必须 `focus({ preventScroll: true })`**，且关闭时若目标已在视口外，不能把它滚进视野——用户停在哪就停在哪。目标控件已被移走（重定向后常见）时，焦点回到 `<body>` 或页面根，绝不用滚动去追。
  - **视口坐标**：打开前后 `getBoundingClientRect()` 的页面内容位置不得变化；用 `visualViewport` 或 `innerWidth - clientWidth` 复核滚动条补偿，禁止出现 1–20px 的横向抖动。
   - **保存后的整页往返（现在是回退路径）**：卡片表单提交到 `options.php` / `admin-post.php` 是 POST + 302 + 重新加载，浏览器必然从 `scrollY=0` 画新文档——这不是弹窗造成的，但用户会一起感知成「位置丢了」。2026-11-23 在实验站量过：首帧在 `y=0`，`readyState=complete` 时才回到原位置，晚约 70ms（页脚脚本最早只能到 `DOMContentLoaded`，赶不上首帧）。所以这条路径上的抖动修不掉，只能绕开：设置卡改走 `form.inplace` 原地保存（§4.1），不再重载；整页提交留给没 opt-in 的卡、自定义 saver 和 `admin-post.php` 下载类动作，它们靠 `ui.js` 在 submit 时把 `路径|page + scrollY` 写进 `sessionStorage.sakuraAdminSaveScroll`、新文档校验同一 screen key 后恢复、读完即删来补救。**screen key 故意不含 `t`**：部分 saver 重定向回来时只带 `page=`、不带 `t=`（对象存储保存存储配置就是这样），带上 tab 会让 key 对不上、恢复静默失效；切页签是链接不是提交，本来就不会写入。**这条记录只服务重载**：原地保存成功后立刻删掉，否则下一次加载会被一个过期偏移拽走。**恢复值只用一次**：`admin.ready()` 末尾清空，之后任何一次弹窗（保存结果、连接测试、首次提示）都不许再动滚动位置。图片/字体晚到可能把文档撑高导致过早的滚动被钳制，所以 `load` 后再幂等校正一次。新增「提交后跳转」的表单不用另写逻辑，但换页面 id 或改成 AJAX 时要确认这条路径仍然成立。
- **尺寸**：`width: min(560px, 100%)`、`padding: var(--g-space-5)`（24px）、`border-radius: var(--g-radius-lg)`（22px）、白底 `--g-card`、`--g-shadow-pop` 阴影；**没有边框**，靠阴影与暖白画布分层。`max-height: calc(100vh - 2 * var(--g-space-4))`（视口高 −36px），内容超高时卡片内部滚动（`overflow-y: auto`）。外层 `.sakura-modal` 是 `position: fixed` + `inset: 0` + `z-index: 100000` 的**无遮罩居中容器**：本身透明，`pointer-events: none` 让点击穿透到页面，只有卡片 `pointer-events: auto`；`padding: var(--g-space-4)`（18px）保证窄屏不贴边。
- **`.sakura-modal--config` 只是语义标记**：仓库里它没有任何 CSS 规则，判断是否为提示弹窗看的是最外层 `.sakura-modal`，不是这个修饰类。
- **结构固定**：图标（46×46、`--g-radius-md`）→ 大写眉标 → 标题 → 1–2 行说明 →（可选）缺失项面板 → 底部「不再提醒」+ 次按钮 + 主按钮。三个变体共用 `render_modal()`，差别只在中段：
  - `modal_html( $options, $context )`（`:233`）—— 配置缺失，有 `.sakura-config-missing` 胶囊面板（小标 + 缺哪几项），主按钮按上下文指向连接页或 `#sakura-s3-connection`。
  - `paused_html( $options )`（`:312`）—— 已停用，无胶囊，主按钮固定去连接页（`Registry::url( 'storage', 'connection' )`）。它只挂在同步中心：连接页上开关就在眼前，再弹一个模态会挡住用户正要点的控件。
  - `reconcile_html( $options, $configured, $has_scan, $busy )`（`:283`）—— 已配置但从未核对，无胶囊，主按钮是 `[data-sakura-action="scan"]`，走页面自己的扫描流程；核对完页面重载、`$has_scan` 成立，弹窗自然不再出现，**不需要**额外的「成功才关闭」状态机。
- **一次只弹一个**：`includes/views/s3-sync-center.php:956-963` 按「缺字段 → 停用 → 未核对」取第一个非空结果渲染，注释是 `One dialog at a time, most blocking first`。新增变体要插进这条链，不要在页面里各弹各的。
- **对齐**：图标、眉标、标题三行居中（图标用 `display: flex` + `margin: 0 auto`，inline 级盒子会被 auto margin 忽略）；说明段与底部操作区保持左对齐 / 两端对齐。说明段不要加 `max-width: 46ch` 之类的行宽上限——中文在这张卡里排到 23 字就折行，右侧空出一大块，看着像排版错误。
- **配置缺失不是错误**：图标用暖灰 `--g-accent-soft` 或中性灰 `.sakura-modal__icon--neutral`，缺失胶囊用 `--g-warn-bg` / `--g-warn`；红色只留给破坏性操作。
- **≤520px**：底部操作区纵向排列、「不再提醒」在上、按钮整宽；次按钮保留描边和暖白底，不能变成无边界的一行字。390 / 320 下弹窗不得横向溢出。
- **打开与焦点**：**同步打开，不等定时器**。自动弹窗由 `initModals()` 在 `DOMContentLoaded` 打开并打上 `data-sakura-modal-instant`（页脚脚本最早只能到这里，所以它是「页面已经画过一帧之后立刻补上」，不是首帧的一部分）；手动打开的弹窗只有 140ms 的透明度淡入。`role="dialog"` / `aria-labelledby` / `aria-hidden` 与 `hidden` 成对切换；**不写 `aria-modal`**——没有模态语义，页面只是被遮罩挡住。打开后 40ms 焦点落标题，所以标题要 `outline: none`（浏览器在非交互元素上画焦点环看着像 bug）。没有焦点陷阱：Esc 与关闭按钮都能关，Tab 可以走出卡片；关闭后焦点回到触发前元素。
- **关闭分两档，且只有一档会写库**：
  - 勾选「不再提醒」后，不论用哪种方式关闭都写 `sakura_imgopt_s3_config_notice_dismissed`，永久保存，直到手动清除该 user meta。
   - 未勾选时**不写任何东西**：X、Esc、次按钮「暂不处理」都只关掉这一次，刷新后状态仍然成立就继续弹。理由是这个弹窗是页面上唯一说明「功能坏了 / 桶不再收文件」的地方，把「关掉」当成「处理过」会让问题静默存在。
  - 1.25.6 及更早的 12 小时 snooze（`sakura_imgopt_s3_config_notice_snoozed_until`）已废弃：升级后读到残留时间戳直接删除，不再压制弹窗。
- **主按钮跳转下一页时**保留 sessionStorage 一次性跳过（`sakuraS3ConfigSkipOnce`），只作为 AJAX 写入失败时的兜底，不能当长期静默用。
- **遮罩在，锁滚动永远不在**：提示弹窗不是模态。2026-11-20 起它有一层遮罩（`--g-overlay` 色调 + `backdrop-filter: blur(3px)`，点遮罩关闭），只做着色与模糊、只动透明度，不位移、不改文档高度、不拦滚轮；`aria-modal` 仍然不写。锁滚动（`position: fixed` 钉 body，或 `html { overflow: hidden }`）会让文档塌陷、视口变宽、整页重排——那才是用户反复反馈的「页面闪一下」，任何时候都不要加回来。确实需要模态语义时（二次确认、媒体预览）另用原生 `<dialog>` + `showModal()`，那两套有自己的 `::backdrop`。
- **节点必须由页面根节点输出**：`.sakura-modal` 是 `position: fixed`，要落在没有 `transform` / `filter` / `will-change` 祖先的位置才能相对视口居中并盖住整块画布（同步中心把弹窗 echo 在 `ob_get_clean()` 之前正是这个原因）。需要它的是居中，不是遮罩。
- **动效只有透明度**：手动打开的弹窗淡入 140ms、关闭淡出 110ms；自动弹窗由 `ui.js` 打上 `data-sakura-modal-instant` 后直接出现（关闭时仍淡出）。`prefers-reduced-motion: reduce` 下两者都关闭。卡片不做位移或缩放：居中的卡片本来就在正确位置，让它「飞进来」只是让用户等它。

### 5.2 二次确认弹窗（`.sakura-dialog`）

破坏性操作与「需要一句确认才继续」的动作走 `SakuraAdmin.ui.confirm( message, options )`（`assets/ui/js/ui.js:75`），不要用 `window.confirm`。列表里的按钮只要写 `data-sakura-confirm="<说明>"`，`ui.js:907` 的 `initConfirmations()` 会自动接管，并默认按危险样式处理。

- **结构**：原生 `<dialog class="sakura-dialog">` + `showModal()`；内部 `form.sakura-dialog__form`（`method="dialog"`）→ `.dialog__body`（`h2.dialog__title` + `p.dialog__message`）→ `.dialog__actions`。不要塞复选框，也不要为了「更热闹」加第三颗按钮。
- **吉祥物只在 `data-mascot="1"` 时出现**：加上之后 `.dialog__body` 变两列（鲸鱼在左、文字在右），鲸鱼节点一律由 `SakuraAdmin.ui.mascot()` 取（`ui.js` 里的 `mascotSvg()`，46×46，已带 `.dialog__mascot` 类）。页面自己拼 `<dialog>` 时也走这个入口，**不要另抄一份 SVG**；取不到时只渲染文字，不要让旧缓存把弹窗带崩（`files-users.js` 的处罚弹窗就是这么写的）。
- **关闭只有一个出口**：自建 `<dialog>` 时把关闭收口成幂等的 `settle()` / `closeDialog()`（`dialog.close()` + 摘节点 + 焦点还原），`cancel`、`close`、取消按钮都调它。2026-11-22 的 `files-users.js` 「取消」调用了不存在的 `closeSanctionDialog`，控制台抛 `Uncaught ReferenceError: closeSanctionDialog is not defined`、弹窗留在原地，只有 ESC 能关——**验收必须真的点一次取消**，只看代码看不出来。
- **样式在 `components.css`「二次确认（Confirm）」段**，不带页面前缀，任何后台页都能用：`width: min(440px, calc(100vw - 32px))`、`border: 1px solid var(--g-line)`、`border-radius: var(--g-radius-card)`（18px）、白底 `--g-card`、`--g-shadow-pop`；`::backdrop` 只铺 `--g-overlay` 色调。注意这几项与提示弹窗**是两套外观**：提示弹窗 560px / 22px 圆角 / 无边框 / 无遮罩，确认弹窗 440px / 18px 圆角 / 有 1px 描边 / 有遮罩，不要互相「对齐」。
- **底部动作区是 `.dialog__body` 的兄弟节点，不放在 body 里**：`.dialog__body` 内边距 `22px 22px 8px`，`.dialog__actions` 是 `16px 22px 20px` + `justify-content: flex-end` + `gap: 8px`。新增变体请保持这个层级；塞进 body 会让左右内边距变成 22/45px（`files-zibll.js` 的输入框变体就是这种写法，属现存的小不一致）。
- **按钮语义**：取消是 `.btn--ghost`，确认在 `danger: true` 时是 `.btn--danger`、否则 `.btn--primary`。`confirm` 返回 Promise：点确认 resolve `true`，取消 / Esc resolve `false`。
- **焦点**：`showModal()` 后主动 `focus()` 确认按钮（`ui.js:140`），所以打开后直接回车就是「确认」——破坏性操作请在文案里把这个后果写清楚，不要靠按钮位置防误触。
- **行为差异要记住**：Esc 能关；**点遮罩不关**（与媒体预览相反）；**不锁页面滚动**——确认弹窗足够小，锁滚动反而会让背景跳位。
- **输入型变体**（`files-zibll.js:100` 的 `ask()`）用于需要填一个值才能继续的动作（延长授权天数、输入「撤销」二字）。输入框沿用第 6 节的 38px 高 / 10px 圆角 / 1px `--g-line-strong`；校验不通过时不要关闭弹窗，也不要把按钮文字改成错误提示。

### 5.3 媒体预览弹窗

- 「文件核对」等列表的文件详情不再跳媒体库，统一用 `SakuraAdmin.ui.mediaPreview(payload, { trigger })` 打开预览。触发元素是 `button[data-sakura-preview]`，属性里放 JSON；PHP 首屏和 AJAX 重绘（`storage-sync.js` 的 `makeRow`）必须输出同一份字段，不能只改一边。
- 多文件浏览：传 `{ items: [payload, ...], index?, labels: { prev, next, counter, gallery } }`。`items` 顺序就是文件顺序，弹窗打开后左右两侧出现 42px 圆形按钮（≤782px 为 38px），舞台顶部居中显示 `当前 / 总数` 胶囊；只有 1 个文件时整组导航隐藏。键盘 ←/→ 切换，触摸横向滑动 ≥48px 且横向位移大于纵向 1.2 倍时切换；切换视频前必须 `pause()`、移除 `src` 并 `load()`。下载按钮、头部大小/状态/位置胶囊和底部路径都跟随当前文件更新，不能只换舞台。
- 结构固定：`<dialog class="sakura-media-dialog">` → 头部（类型 + 扩展名眉标、文件名、大小/状态/时间/本地或云端胶囊、38px 关闭按钮）→ 媒体舞台 → 底部（对象键/路径 + 下载主按钮）。不要用 `alert` / `confirm` / 浏览器原生视频控件，也不要把 `<dialog>` 的 UA 默认边框、内边距、按钮样式和聚焦黑描边直接露出来；`dialog` 自身聚焦时用 `outline: 0`，键盘焦点由内部可操作元素的 `:focus-visible` 承担。
- 尺寸：`width: min(1040px, calc(100vw - 48px))`、`max-height: min(88vh, 920px)`、24px 圆角、1px 暖灰描边、`--g-card-surface` 白底、强阴影；`::backdrop` 用 `rgba(18,19,21,.62)` + `blur(8px) saturate(.9)`。媒体舞台使用与插件画布一致的暖白渐变（`#f8f7f3 → #f4f3ee → #f7f6f2`），空状态/错误提示用墨色文字而不是白字；视频舞台仍为深色以承载自绘控件。图片 `object-fit: contain`，最大高度 `min(calc(62vh - 40px), 610px)`、舞台内边距 20px，图片四周至少留 20px，不能被裁切或出现内滚动条。
- 类型差异：图片直接展示 + 下载；视频用自绘控件播放 + 下载（播放/暂停、当前时间/总时长、进度、静音、音量、全屏；支持 Space 播放暂停、←/→ 前后 5 秒），`<video>` 不写 `controls`；压缩包、文档及其他类型不加载媒体，只显示「暂不支持在线预览」说明 + 下载按钮。下载按钮始终是主按钮，`href` 走带 nonce 的 `admin-post.php`（对象存储用 `action=sakura_s3_media_download`；删除申请用 `action=sakura_sufm_download&attachment=附件 ID`），响应头必须是 `Content-Disposition: attachment`，不能直接给 CDN 直链（跨源时 `download` 属性会失效）。
- 文件空间「审核与执行」的删除申请队列，对象单元格只放「N 项 / 大小」两行；「查看文件」和「批准 / 驳回」一起放在操作列，不再在对象列另起一个文字按钮。点击后才请求 `admin/delete-requests/{id}/items`，不要把每个文件的预览 URL 塞进队列表。响应里的文件夹项要展开冻结快照中的实际文件，快照为空时用文件夹说明占位。多文件仍复用同一个媒体预览弹窗，不另写一套画廊。
- 审核队列操作列：待审核行依次是「批准」(primary) /「驳回」(ghost) /「查看文件」(ghost)；`item_count` 为 0 时省略「查看文件」。操作按钮语义固定——批准只把申请推进到可执行，不删除；驳回退回申请并立即解除对象锁；「需核实」不再作为按钮出现（历史行仍可能带 `needs_review` 状态，按待审核同样处理）。
- 操作列的单元格本身必须是普通 `td`（保持 `vertical-align: middle`），按钮组放在内部的 `.queue-actions` flex 容器里。不要给 `td` 直接加 `display:flex`：那会让单元格脱离表格垂直居中，按钮比状态胶囊高出一截。验收标准是按钮中线与同行的状态胶囊、提交时间中线偏差 ≤2px。
- 行为：`showModal()` 打开，焦点落在 `dialog` 容器但不显示 UA 焦点环；Esc、点遮罩、点关闭都能关；关闭后焦点回到触发按钮；打开期间用 `body { position: fixed; top: 当前 body 的视口位置 }` 固定页面，并只给 `html` 加 `sakura-media-open` 锁根滚动；不要给 `body` 设 `overflow: hidden`（Chrome 会把页面滚回顶部）。关闭时恢复 body 内联样式并 `scrollTo` 回原位置，`trigger.focus({ preventScroll: true })` 避免焦点回退再次滚动；关闭视频要 `pause()` 并清空 `src`，避免后台继续解码。图片加载失败、视频解码失败、没有可预览地址分别给独立标题和说明，不要只显示一串英文错误。
- 移动端 ≤782px 全屏：`100vw / 100dvh`、无圆角无边框、头部/底部内边距收窄、下载按钮整宽、音量条隐藏；320px 下标题可换行，弹窗和页面都不能横向溢出。
- `prefers-reduced-motion` 下关闭入场动画；遮罩和弹窗动画只做透明度和轻微位移，不做缩放弹跳。

## 6. 控件

- 输入框、下拉、文本域：38px 高、10px 圆角、1px `--g-line-strong` 边框、白底、14px 字。文本域最小高度 88px，可纵向拉伸。
- 挨着输入框、下拉并排的按钮属于同一个控件行，高度必须等于 `--g-ctl-h`：`--g-btn-h`（36px）与 `.btn--small`（30px）只给卡头、表格行内这类不跟输入框并排的位置。判据与写法见 10.2。
- 输入框、下拉的 `width:100%` 只表示填满所在字段列，不是填满卡片；筛选行、工具行和短字段必须按 10.2 的上限表限宽。勾选/单选固定 18×18、开关固定 38×22，都不参与列宽拉伸。
- 颜色字段用 `UI::field( 'type' => 'color' )`：与输入框同高、同边框，内层 swatch 留 1px 暖灰内描边并跟随 10px 圆角（纯白卡片底色也要能看出色块边界）；不要手写 `<input type="color">` 绕过组件。`::-webkit-color-swatch` 与 `::-moz-color-swatch` 必须拆成两条规则：合并后 Chrome 不认识 Mozilla 伪元素，会把整条规则丢弃（实测边框不生效）。
- 勾选框与单选框都是 18px 圆形：勾选态是「樱花淡粉圆盘 + 白色圆心」（`--g-check-fill` `#FFAACA` 底、6px `--g-select-dot` 白点、`--g-check-line` 描边），未选态是 `--g-select-surface` `#fffdfd` 底 + 1px `--g-select-border`，hover 描边 `--g-select-border-hover`。这是开发者 2026-11-21 定的形态：**不要再用方框 + 勾号，也不要深樱实心**。
- 白点是 6px 绝对居中：`::before{ position:absolute; top:50%; left:50%; width:6px; height:6px; margin:0; border-radius:50%; transform: translate(-50%,-50%) scale(0) }`，`:checked` 时 `scale(1)`。**`margin:0` 与 `float:none` 不是冗余**：WordPress 后台 `forms.css` 的 `input[type="checkbox"]:checked::before` 会注入 `margin:-3px 0 0 -4px`、`float:left`、`width/height:1.3125rem` 和自带的勾号 `content:url(…)`，不清掉白点就会漂到左上角。
- 禁用态为暖灰底/边框 `--g-wash` + `opacity:.6`；`checked:disabled` 保持 `--g-check-fill` 底 + `opacity:.75`，让「锁定但已勾选」仍然看得出来。
- **值被锁定（不是暂时禁用）时用「小锁 + 状态词」，不要只把复选框灰掉**：挂锁只有一份路径数据，在 `UI::lock_icon()`（`src/Admin/UI.php`），权限矩阵的锁定格（`.caps-matrix__fixed`）与「上传行为」的冻结开关（`.check__lock`）都印它，两处不许各存一份 SVG。锁定行里已经没有可点的控件，所以容器从 `<label>` 换成 `<div>`（`<label>` 指向不存在的控件等于空标签），并补 `screen-reader-text`「（已锁定，当前为开启／关闭）」和可见的状态胶囊：`已开启` 用 `--g-ok` 压 `--g-ok-bg`（5.72:1），`已关闭` 用 `--g-muted` 压 `--g-paper-deep`（5.67:1）。灰掉的复选框只说「你不能动」，从不说明它现在是开还是关——对「上传成功后删除本地文件」这种开关，那正是最要紧的一条信息。
- 焦点只在 `:focus-visible` 画：`outline: 2px solid var(--g-select)` + 3px `--g-select-focus` 外阴影。WP core 在普通 `:focus` 上还挂了一条双环 `box-shadow`，要显式压回去（`:focus{ outline:0; box-shadow: inset … }`），否则鼠标点一下也会留下蓝灰环。
- 选择控件放在 flex 行里时必须 `flex: none`（或 `0 0 18px`），否则在 320px 会被压成 16px 宽。宽度和高度都属于硬性 18px。
- `appearance: none` 的基础态写了白底后，`:checked` 必须用同等或更高特异性重新声明背景和边框，否则基础态会把勾选态盖掉。
- **单开单关的布尔项用滑动开关**：`label.check` 里放 `<input class="is-switch" type="checkbox">`，`UI::field` 的 `type=checkbox` 与 `type=toggle` 都输出这一个。轨道 38×22、`--g-radius-pill`；**关闭是米白 `--g-switch-off` `#F6EFE2`，开启是樱花淡粉 `--g-switch-on` `#FFAACA`**（开发者 2026-11-21 定，原先的绿轨道作废），旋钮 16px 白 `--g-switch-knob`，开启位移 `translateX(16px)`。
- 开关两态都很浅，所以轨道要有 1px 内环（`--g-switch-off-line` / `--g-switch-on-line`）、旋钮要有 `--g-switch-knob-line` 发丝边加投影：只靠填充色的话，白旋钮会融进米白轨道。旋钮 `::before` 同样要 `margin:0; float:none`——不清掉 WP 那条负边距，旋钮会从 19px 被拖回 15px，看起来像「开着但没滑过去」。
- **多选清单与「勾选＝禁用」这类反向语义不要用开关**：一个开关说不清「这个、那个、还有那个」，浅粉的「开」也会把「禁用」说成好事——尺寸表的禁用列、权限矩阵、支付通道、表格全选/行选一律留勾选框。历史变量 `$sufm_space_switch` 只是兼容名，输出必须是 checkbox；交互确认仍通过 `data-zibll-switch` 绑定，不依赖控件外观。
- 不在页面根节点内的原生控件（如布局工具条的「显示网格」）要单独给皮肤。
- 焦点环统一为 3px `--g-select-focus` `rgba(157,52,82,.16)`，边框变 `--g-accent`；不要使用蓝色 outline。
- 主按钮是深樱实心白字（`--g-accent`，上浅下深的三段渐变 + `--g-accent-line` 描边，见 `components.css` 的 `.btn--primary`）；次按钮白底描边（页头操作即使传 `quiet` 变体也不能无边框）；危险按钮只在确认场景实心 `--g-bad`。按钮不要再写死颜色，也不要给某一种变体单独换色相。
- 表格表头 12.5px、正文 13.5px；数字列可等宽字体，但不要用蓝色。
- 多列勾选/选项网格里的说明文字必须 `grid-column: 1 / -1` 单独成行，不能被误读成某个选项的标签。
- **模板/占位符一类的字符串字段用「输入框 + 占位符卡片 + 预览」的组合控件**（`.rule-composer`，样式在 `assets/ui/pages/image.css`，字段在 `includes/class-image-optimizer-module.php::field_rename_rule_cb()`）：卡片是 **`aria-pressed` 开关而不是普通按钮**——点未选中的按 `-` 拼到末尾（唯独 `{ext}` 用 `.`，扩展名与主名之间只能有点号；末尾已经是 `-`/`_`/`.` 时不重复插入），点已选中的把该占位符连同一侧连接符一起去掉、留下的分隔符收拢成一个；**同一个占位符只能用一次**，卡片自己按下时整块换樱花淡粉 `--g-brand-petal`（#FFAACA，与顶栏品牌瓦片同色）压墨字 `--g-ink`（8:1；**不要白字**，白字在这个底色上只有 1.77:1 完全读不出来），一眼能看出规则里已经在用哪几个，服务端要按已保存的规则渲染初始 `aria-pressed`，别让首屏空白等 JS。预览行给出示例文件名，示例值必须由服务端提供（`Upload_Renamer::preview_tokens()` / `preview_filename()`），不要在前端另写一份占位符表。这类字段不要再留一整段「可用占位符：…」的说明文字去填满卡片，卡片本身就是说明。
- **用户自定义的占位符值（`{fixed}`）单独一个字段，卡片用虚线边与内置占位符区分**：值只收 `[A-Za-z0-9_-]`、最长 24 个字符（`Settings_Repository::rename_fixed()` 再洗一次，防库里写入脏值），因为这段文字会落进文件名——中文、空格、emoji 在部分服务器 / 网盘 / 下载工具里会乱码，所以保存时直接去掉并给一条 `add_settings_error( ..., 'warning' )` 提示，别静默吞掉用户的输入。字段说明里要写清「不建议使用中文」和为什么。自定义占位符为空时，`{fixed}` 只连同**它前面**那一个连接符一起去掉、再把留下的双分隔符收拢成一个（`preg_replace( '/[-_.]?\{fixed\}/', '' )` + `preg_replace( '/([-_.])[-_.]+/', '$1' )` + 去首尾分隔符）；两侧都吃会把邻居粘成 `{hash}{filename}`。PHP 与前端预览必须各实现一遍、结果一致，否则预览会承诺一个上传时不会出现的前缀。
- **占位符超过十来个就分组，不要平铺**：用得少的收进「更多占位符」折叠区（`.rule-composer__more` + `.rule-composer__tokens--more`，服务端按已保存规则里是否出现这些占位符决定初始展开，前端只翻 `aria-expanded` 与 `hidden`）。十七张卡片铺开会把卡片撑成一堵墙，而折叠区里那些本来就用得少。
- **重命名规则作用于所有上传文件，不只是图片**（开发者 2026-11-21 指出：上传的还有压缩包、视频、文档）。所以：扩展名永远原样保留（后端用 `str_ends_with( strtolower( $new_name ), '.' . $ext )` 判断要不要补，不要用 `pathinfo()` 比字符串——`backup.tar.gz` 的扩展名是 `tar.gz` 不是一个 `gz`），没有扩展名的文件直接跳过重命名；取不到值的占位符（`{wxh}` 对视频/压缩包、`{hash}` 对超过 32 MB 的大文件、访客上传时的 `{user}`）一律连同连接符一起去掉，别在文件名里留空段——「给一个 2 GB 视频算 md5」这种代价必须在代码里挡住，并且落在字段说明里告诉用户。

## 7. 移动端

- ≤900px：页头改单列，说明和操作按钮依次排列；按钮可以换行，不要横向滚动，也不要压住状态卡。
- ≤782px：卡片标题区换行，标题占满一行，操作按钮落到下一行并右对齐。
- 页签保持单行：`gap: clamp(10px, 2.8vw, 18px)`、字号 13px；横向滚动时两端用 mask 渐隐，不能露出半个字。验收时最后一个页签必须完整可见。
- 分段控件、日志筛选允许换行；不要用横向滚动藏按钮。
- 表格用 `.table-wrap` 内部滚动，页面本身不横溢。桌面的固定列宽在 ≤782px 必须重置为 `width:auto; min-width:0`。
- 内容型表格（审核队列、授权流水、套餐编辑器）在窄屏重排为带标签的行：数据行用 `data-label` + `::before` 显示列名，表头隐藏；空标签 `data-label=""` 的单元格保持块级，不加冒号。
- 审核队列在 ≤782px 不用默认的 92px 标签沟槽，改成「标签 | 值」两行式紧凑列举：行用 `display:grid; gap:9px; padding:14px 0`，单元格是 `grid-template-columns: 62px minmax(0,1fr)` + `align-items:baseline`，列名 12.5px `--g-muted`（不是 11.5px 的暗淡眉标），用户 ID 与大小这类补充行升到 12.5px `--g-muted`。操作行 `grid-template-columns: minmax(0,1fr)`、隐藏 `::before`、上方 1px `--g-line-soft` 分隔线，按钮靠右、高 34px、字 13px。没有操作的行（`td.queue-cell.is-empty`，由 JS 打标）整行隐藏，不要在卡片里留一条孤零零的「—」。验收：390 下每行信息区首行顶到卡片左内边距，按钮右缘等于单元格右缘，320 不横向溢出。
- 桌面顶栏是三列 grid：品牌左、模块导航绝对居中、状态/动作右；导航中心必须等于页面内容中心，不能被左侧品牌文字宽度推偏。≤1100px 回到 flex-wrap，品牌与状态一行、模块导航整行另起。≤660px 收成「品牌 + 状态」一行；≤340px 隐藏长状态胶囊，避免挤成三行。

## 8. 常见坑

- 后台 tab 参数是 `t`，例如 `admin.php?page=sakura-tools-image&t=thumb`；不是 `tab`。截图验收时用错参数会全部落在默认页。
- 资源门控只看 `Route::current_page()`，不再有迁移白名单。新页面只要注册了路由并调用 `Assets::enqueue_page()` 就会加载 UI 栈。
- 隐藏页面（如批量处理）不在 `Registry` 里，不要调用会反查路由的 `Assets::enqueue_page()`；直接 `Page_Assets::set_data()` + `Page_Assets::enqueue( 'media-progress' )`。
- WP 媒体库样式已迁到 `assets/ui/wp-media/`；不要放回 `assets/` 根目录，也不要让它们参与后台页面布局。后台页面出现 `media-modal-folders.css` 是媒体弹窗的全局依赖，不是页面样式串场。
- 窄屏重排用的 `data-label` 要加在真正承载列名的元素上，且只加一次；`::before { content: attr(data-label) }` 不会走翻译，当前后台仅中文，新增语言时需改为视图内可见标签。
- 勾选框最容易出现「看着能点，但勾没勾一个样」：基础态选择器特异性高于 `:checked` 时，白底会把深樱勾选态盖掉；要在同一特异性补 `:checked`。
- 勾选框白点跑到左上角：先看 `::before` 的计算样式。根因通常是 WP 后台 `forms.css` 的 `checked::before` 负 margin 与 grid/flex 居中冲突；按第 6 节改成绝对定位 + `margin:0`，不要用 `!important` 硬盖。
- 支付方式少了支付宝：页面只渲染主题实际启用的通道。测试站先查 `zibll_options['pay_alipay_sdk_options']` 是否为 `null`；生产为 `official_alipay` 且 `pay_sdk_order.alipay=1`。这是主题数据差异，不要把支付宝开关硬编码进视图。
- 卡片宽度不对：查 `Layout::PAGES[布局 id]['cards']` 里有没有这张卡，以及 `Layout::layout_for_page()` 的别名对不对。系统设置页页面 id 与布局 id 都是 `system-settings`。
- 布局工具条文案竖排用「一字宽块 + 自然换行」：`width:1.1em; white-space:normal; word-break:break-all; line-height:1.34; text-align:center`，不要用 `writing-mode: vertical-rl`。部分 CJK 回退字体在这里上报的纵向步进只有约 4px，四字会叠成一团（实测标签高 4.17px）；编辑态恢复 `width:auto; white-space:nowrap; word-break:normal`。改完在 1440 和 1101 截图检查四字完整。
- 重构后按钮/操作入口不见：先按 10.1 的操作清单对照，确认是不是在搬卡片、换布局时删了 DOM；不要用 CSS 补一个只有外观的假按钮，也不要把入口藏进折叠区。
- 筛选框/输入框铺满整行：全局输入框的 `width:100%` 只填字段列，检查父级是否给了 `flex:1` 或没有 `max-width`；按 10.2 的上限表改父容器，不要在每个页面单独写 `!important`。
- 多选组（源格式、尺寸等 chip）的说明段落不要放进 grid：`<p class="description">` 会成为网格项，把同一行最后一个 chip 拉到说明块的高度（实测 103px 的竖长框）。说明放在 grid 外的 notes 容器里，用分隔线与 chip 区分。
- 全宽表格的滚动容器只包 `<table>`：说明段落放进容器会被负 margin 一起拖到卡片边框（≤782px 尤其明显）。说明放在滚动容器外，让它继承卡片内容区内边距。
- 跨页切换动画只在 `base.css` 的「Page change」段定义，别在页面 CSS 里另写。WordPress 7.0 起后台全局启用 View Transitions，本插件用 `@view-transition { navigation: none }` 退出，改成「新文档硬切 + `.sakura-admin__main` 180ms 淡入上浮」；点击后那 ~300ms 是 WordPress 引导，靠 `core.js` 在点击的同一帧点亮 `.sakura-nav-bar` 补反馈。**不要给元素加 `view-transition-name`**：命名会让浏览器多拍一次快照并单独分组渲染（实测净增约 15ms），而且 root 组的整页交叉淡化照样在跑，两页文字仍会互相穿透。预取也不可行：登录态后台响应头是 `no-store`，Speculation Rules 不会发出请求。
- 验收宽度跟着改动范围走，不机械跑固定清单：
  - 单页/单组件、未动响应式：1440 即可；
  - 单页/单组件、动了响应式：1440 + 390；
  - 共享 `tokens` / `base` / `components` / 全局布局：1440 覆盖全部后台路由，390 抽查至少 3 个代表页；
  - 页面骨架或断点：再补 1366、1101、782、424、320。
- 每轮都检查 `document.documentElement.scrollWidth == clientWidth`、`.page-body` 相邻块间距 ≥16px、同一卡片无 `.switch` / `.check` 混用、每张表只有一个 `<thead>`，并确认 console 无报错。

## 9. 组件层与静态资源

### 9.1 PHP 组件

- 页面用 `UI::page( $args, $body )`。`$args`：`id`（页面 id，写入 `data-sakura-page`）、`module`、`tab`、`eyebrow`、`title`、`lede`、`status`、`actions`、`chrome`。
- 卡片用 `UI::card( $args, $body )`。`$args`：`id`、`kicker`、`title`、`description`、`actions`、`wide`、`class`、`anchor`、`form`、`save`。`actions` 的每一项：`label`、`url`（链接）或 `button => true`（按钮）、`variant`、`id`、`attrs`。
- 表单用 `form` 参数：
  - `id`：表单 id，默认 `sakura-card-form-{card}`；
  - `action`：默认 `options.php`；自定义 saver 传 `admin-post.php`；
  - `option_group`：传给 `wp_create_nonce( $group . '-options' )` 的组名；
  - `markers`：`fields`（默认）、`option_fields`、`none`；
  - `option`：`markers=option_fields` 时的 option 名；
  - `hidden`：额外 hidden 字段。
- 字段用 `UI::field( $args )`，类型支持 `text/number/url/password/email/color/select/textarea/checkbox/radio/toggle/hidden/custom`；复杂控件用 `custom` + `control` 回调，只外包标签与间距。
- `toggle` 与 `checkbox` 现在输出同一个控件（`type=toggle` 等于 `checkbox` + `.is-switch`，见第 6 节）；`toggle` 只是历史别名，新代码写 `checkbox` 加 `sw` 语义即可。
- 反馈用 `UI::badge()`、`UI::alert()`、`UI::notice()`、`UI::empty_state()`、`UI::modal()`。动作结果用 `UI::modal()`，持续状态用 `alert`/`notice`，AJAX 小动作用 `admin.ui.toast()`（见 5.1）。
- 新页面不要手写 `section.card > .card__head > .card__body` 骨架，也不要在视图里重复 nonce、卡片标记和保存按钮。特殊版式通过 `wide` / `class` 传给组件，不改组件结构。
- 组件在 `src/Admin/UI.php` 与 `src/Admin/UI/`，`Card_Form` 在 `src/Admin/Card_Form.php`，均由 PSR-4 自动加载。

### 9.2 页面接入

- 在 `src/Admin/Registry.php` 注册页面与 tab；页面 id 同时决定 CSS/JS 文件名。默认 tab 可以省略 `t`。
- 渲染前把该页需要的运行时数据交给 `Page_Assets::set_data( $page, $data )`，再调用 `Assets::enqueue_page()`。数据会进入前端 `SakuraAdmin.data`。
- 页面 CSS 命名：`assets/ui/pages/{module}.css` 是模块共享样式，`assets/ui/pages/{page}.css` 是可选页面样式；JS 只加载 `assets/ui/js/pages/{page}.js`。
- **卡片位置是静态的**（1.27 起）：`src/Admin/Layout.php` 的 `Layout::PAGES` 为每个页面声明 `order`（阅读顺序）与每张卡的 `array( 行, 列, 跨列数 )`，`UI::card()` 把它们写成行内变量 `--g-card-row` / `--g-card-col` / `--g-card-span`，再由 `components.css` 的 `.card-grid > .card` 转成 `grid-row` / `grid-column`。视图根节点输出 `data-sakura-layout="布局 id"`，每张卡带 `data-sakura-card`；新卡的布局 id 由 `Layout::layout_for_page()` 解析（`storage-deletes` → `deletes` 等）。
- 布局 id 与页面 id 可以不同（如 `files-zibll` 用 `files-space` 的排布）。改页面 id 时别顺手改布局 id，否则得同步改 `Layout::layout_for_page()` 的别名，卡片会退回默认宽度。
- 没有右侧工具栏、没有拖拽、没有 46px 预留留白，也没有 `sakura-layout-enabled` 类。卡片用 `grid-auto-rows: min-content`，一行只取该行最高卡的实际高度。
- 行号是显式的：视图按代码顺序输出卡片，未必等于阅读顺序，只靠 `grid-column` 会让 CSS 按 DOM 顺序打包而留下空洞。改排布时**同时改 `order` 与 `cards` 的行列**，两者必须描述同一批卡片（有测试守着）。
  - **不要再靠推断**（顺序、`col`、单个 `h`）判断「有没有排过」：引擎每次加载都会把自己的顺序/列写回，旧数据里也残留过零散高度值，推断会把没排过的页面误判成排过，于是又闪。
- `reflow()`（`layout-refresh` / 断点切换）只在 `editing` 为真时重打包，否则一次 AJAX 重绘会把普通页面悄悄切成画布。
- 保存过的高度（`data-sakura-h`）在流式下退化为 `min-height`：保住用户设定的下限，又不会把卡片拔出文档流。
- **不要给卡片加首屏隐藏规则**。1.27 之前有一条 `visibility: hidden` 等 JS 落位后再显示的规则，落位失败时整页卡片空白两秒（就是「卡片被延迟加载」）。现在卡片位置在服务端就定了，首帧即可见。
- 页面脚本只用 `window.SakuraAdmin`：`ready`、`qs`、`qsa`、`on`、`delegate`、`closest`、`dataBlock`、`format`；请求用 `admin.api.ajax/post`；提示/确认/忙碌用 `admin.ui.toast/confirm/busy`。不要引入 jQuery。
- 所有可见文案走 PHP 的 `__()` 后放进 `Page_Assets::set_data()`，JS 不内嵌未翻译中文。
- 表格/列表 AJAX 渲染后可以继续 `admin.events.emit('layout-refresh')`，但**不再需要重排**：卡片由 CSS Grid 排布，行高随内容自适应，异步内容不会压到页脚，也不会重新定位卡片。
- 迁移/新增页面后验证 1440/1366/1101/782/424/390/320、逐卡保存与控制台；**不测拖拽**（已移除）。

### 9.3 React 岛屿与 REST 保存

系统设置（`admin.php?page=sakura-tools`）从 1.28.8-beta-3 起是第一个 React 岛。它演示的规矩对后续页面同样适用。

- **分工不变**：PHP 仍负责页壳、页头、页签、菜单、翻译与权限；岛屿只接管内容区。视图输出 `#sakura-system-root`（先放一句「正在读取环境信息…」）和一段 `<script type="application/json" id="sakura-system-bootstrap">`，数据由 `System_Payload::build()` 生成。首屏内容因此仍是服务端吐出来的，不是白屏等 JS。
- **源码与产物**：源码在 `assets/ui/src/{page}/`（`index.jsx` 挂载、`boot.js` 读引导数据与写样式、`components.jsx` 复刻 `card` / `field` / `sakura-modal` 标记、`app.jsx` 状态与保存）；产物 `assets/ui/dist/{name}.js` 由 `node bin/build-ui.mjs` 生成，**必须提交**——`bin/build-plugin-zip.sh` 用 `git archive` 只打包已跟踪文件，没提交的产物不会进发布包。发布前重跑一次 build，别把本地未编译的源码当成品。
- **标记复用**：岛屿里的卡片、字段、弹窗要输出与 PHP 组件同名的 class（`card` / `card__head` / `card__title` / `field` / `field__label` / `sakura-modal__card` …）。自创一套 class 会让令牌、V2 阴影与断点规则全部失效。
- **样式写回**：外观项在客户端写 `.sakura-admin` 的行内变量（`--g-page-max`、`--g-radius-card`、`--g-card-border-width`、`--g-shadow-card`、`--g-grid-gap-x/y`）。值等于默认值时用 `removeProperty`，不要写回默认值——令牌表必须保持唯一来源。
- **岛内的区块间距要自己补**：`.page-body` 的 `> :not(:first-child) { margin-top: var(--g-stack) }` 只给 PHP 渲染的兄弟节点留白，React 根永远只有一个子节点，这条规则命中不了它里面的区块（症状是 KPI 票根和卡片网格贴在一起）。系统设置在 `pages/system.css` 里用 `#sakura-system-root .kpis--ticket + .card-grid { margin-top: var(--g-grid-gap-y) }` 把这段间距接到「卡片间隔」上——以后往岛里加区块，间距同样要显式写。
- **保存走 REST**：`POST /wp-json/sakura-tools/v1/system/layout`，带 `X-WP-Nonce`（引导数据的 `rest.nonce`）。服务端 `System_Layout_Settings::merge()` 先把入参并到现值上再 `save()`，所以缺字段不会清空、越界会被 clamp，响应返回 `{ layout, notice }`；前端用返回的 `layout` 回写界面（`sanitize()` 可能改过值），用返回的 `notice` 打开弹窗——提示文案只在 PHP 里写一份（`System_Payload::saved_notice()`）。
- **REST 路由必须挂在无条件装配的模块上**。`/wp-json/` 请求不是 admin 屏幕，`if ( is_admin() )` 里装配的模块所注册的 `rest_api_init` **根本不会执行**，症状是保存 404、`/wp-json/` 的 `namespaces` 里没有本插件命名空间。系统设置的 `src/Admin/Rest/System_Routes.php` 就是为此单列，由 `Plugin::build_modules()` 无条件加入。
- **岛屿内的弹窗必须 portal 到 `.sakura-admin`**，不能挂到 `body`：`components.css` 的模态选择器都带 `.sakura-admin` 前缀，且 `main` 的进场 `transform` 会成为 `fixed` 的包含块，挂错了不是没样式就是跟着 `main` 一起抖。
- **关闭后的焦点**：先还给触发按钮；保存成功后按钮因「没有改动」而 `disabled`，收不到焦点，所以要有回落目标（卡片标题加 `tabIndex="-1"` 与 `data-sakura-return-target`），不能把焦点丢给 `body`。
- **保存成功后清掉 `sessionStorage` 的 `sakuraAdminSaveScroll`**：`ui.js` 在任何 `options.php` 提交上都会记录滚动位置，岛屿不导航，这条记录只会被之后某次刷新重放。
- **保存中的按钮不要只换文案**：`.card__savebar` 是右对齐的，「保存布局设置」换成「保存中…」会让按钮一下子窄 28px，分隔线跟着回缩，保存期间弹回来两次——看起来就是卡片在抖。用 `BusyLabel`（两层文案叠进同一个 grid 单元，宽度取较宽的那个）或者干脆不换文案，只靠 `is-busy` + `aria-busy`。同理，任何会改宽高/换行的加载态都不该出现在保存条里。
- **保存条里的按钮不做 hover 抬升**：`.btn:hover` 的 `translateY(-1px)` 在这一处会连抖三次——按下（`:active` 回落 1px）、松开（恢复 -1px）、保存完成提示框的遮罩盖住指针（hover 断开，抬升消失，再沉 1px）。所以 `components.css` 里把 `.card__savebar .btn` 的 `transform` 钉成 `none`，只保留颜色与投影变化。同理，提示框的进出场只动 `opacity`（`sakura-modal-fade-in/fade-out`），不要 `translateY` 或 `scale`——弹窗卡片自己移动，比什么都显眼。
- **验收（系统设置）**：1440 与 390 下首屏直接有内容、无横向溢出；改一项后保存按钮才可点；保存后不重载、每帧 `scrollY` 相同、无 layout shift；外观项当场生效（改回默认后行内样式消失）；弹窗在视口内，Esc / 点遮罩 / 按钮都能关，关闭后焦点落在卡片标题；`sessionStorage` 已清空；未登录 `GET /wp-json/sakura-tools/v1/system` 返回 401。

## 10. 重构守恒与控件尺寸

这一节来自 2026-11 几次后台改版的回归：整页重构时删掉了原有按钮，操作区被挪到别处，筛选框和输入框又被 `width:100%` 拉满。以后按「先守恒、再限宽、后验收」执行，不要把一次样式调整做成整页重写。下面的宽度是验收标准，不会由全局 CSS 自动套用；具体页面和组件要在父容器上实现上限。

### 10.1 重构守恒：只改表现，不删功能

- 样式重构的边界是外观和排布，不是信息架构。页面 id、tab 参数、路由、卡片 id、表单 `name` / option 键、nonce、`data-*` 绑定、按钮 `id`、JS 初始化入口都不改；确实要改时单独提交，并保留旧地址和旧 option 的兼容。
- 动手前在 1440 和 424 各截一张图，并清点当前页面的操作入口（按钮、链接、下拉、保存条）和表单控件（输入框、勾选框、单选、文本域）的数量与文案。改完用同一份清单逐项对照：操作入口数量不得减少，表单控件不得减少；确认重复或被等价控件替代的除外，但要在清单里写明替代关系。按钮文案不得悄悄换成同义但更难懂的说法。
- 不允许以「统一」「精简」「更像新版」为理由，把卡头操作、保存按钮、导出、刷新、返回等入口删掉、藏进折叠区、降级成纯文字或移到页面底部。要删或合并入口，必须同时满足：只有这一个入口重复、替代入口可见且能完成同一件事、在提交说明里写明删了什么、为什么删、替代入口在哪。
- 去重时保留一个可见入口，不要整组删掉。删除队列用卡内四个状态块替代「全部状态」下拉，但状态块和空状态的返回入口必须保留；S3 文件核对把操作移到卡头后，筛选行、搜索框和原有 JS 绑定仍要在。
- 桌面默认布局守恒：页头（眉标 → 标题 → 说明 → 操作，状态卡在右）、卡片顺序、卡头操作（右上）、卡内保存条（右下）、筛选行（卡内第一块）都保持原位。允许因文案变长、控件换行带来的高度变化，不允许无故换列、换行、把卡头按钮搬到卡内、把保存条搬到页面底部。需要调整顺序时改 `Layout::PAGES` 的 `order`，不要只靠 `order` 属性让视觉顺序与 DOM 顺序脱节——键盘 Tab 顺序跟着 DOM 走。
- 窄屏重排是唯一允许的大幅位移：≤1100 / ≤782 可以单列、换行、把动作落到标题下方，但 1440 的默认布局不能先按移动版堆叠。
- 一次提交只做一类事：布局重构不要顺手改路由、改文案、改 option 名、改组件 API；反过来，功能改动也不要夹带整页样式重写。单页重构尽量一页一个提交；共享组件改动要列出受影响页面。提交说明写清保留了什么、移动了什么、删除了什么。
- 如果页面确实需要重新设计而不是修样式，按新页面处理：先说明目标与信息架构，拿到确认，提供改版前后 1440/424 截图，不要混在「样式微调」里。

### 10.2 控件尺寸：`width:100%` 只填自己的列

全局输入框、下拉、文本域默认 `width:100%`，含义是填满所在字段列，不是填满卡片。父容器必须给上限；筛选行、工具行、字段行都不能让一个控件吃掉整行。

| 控件 | 建议宽度 | 上限 | 写法 / 说明 |
| --- | --- | --- | --- |
| 列表搜索框 | 240px | 280px | `flex: 0 1 240px; width: 240px; max-width: 280px`，不要 `flex:1` |
| 状态/类型筛选下拉 | 160px | 180px | `width:auto; min-width:140px; max-width:180px`，按最长选项定宽 |
| 短文本（名称/标题/slug/备注） | 260px | 360px | 放在两列字段网格里，只填自己的列；列更宽时加列，不拉长控件 |
| 数字（端口/容量/间隔/条数） | 112px | 140px | `max-width:140px`，不要和 URL 同宽 |
| URL / 路径 / 长文本 | 100% 列宽 | 560px | 单列长字段用 `field--full`，控件 `max-width:560px` |
| 密码 / 密钥 / Token | 100% 列宽 | 420px | 不要为了「看得全」把密钥框拉满整张卡 |
| 颜色 | 48px | 56px | 与输入框同高 38px，不要拉成一条 |
| 文本域 | 100% 列宽 | 640px | 多行说明才用；不要用文本域代替单行短文本 |
| 勾选框 / 单选框 | 18×18px | 18×18px | `flex:0 0 18px`，永远不随容器拉伸 |
| 滑动开关 | 38×22px | 38×22px | `flex:0 0 38px`，轨道不拉伸、旋钮 16px |
| 按钮 | 内容宽 | — | 卡头小按钮 30px 高；普通按钮 36px；桌面不做整宽按钮 |

整宽按钮只允许出现在 ≤782px 的卡片保存条、弹窗底部和空状态主操作；桌面卡头、卡内和筛选行按钮一律内容宽。

补充：

- 字段网格默认两列，列宽 `minmax(0, 1fr)`；≤1100 改单列。单列时输入框可以填满卡片内容宽，但 URL/路径/密钥仍要遵守 420–560px 上限，不能一路铺到 1200px。
- **并列控件的边框高度必须一致，不是底边对齐。** 输入框、下拉是 `--g-ctl-h`（38px）的盒子，跟它们并排的按钮就不能保留自己的 `--g-btn-h`（36px）或 `.btn--small`（30px）：2px 的差在 1:1 截图里就是「按钮矮一截」，8px 的差（`获取 SDK 参数` 曾被压到 30px）是一眼能看出的错位。正确写法是给同一行里的按钮显式抬到控件高度，不要用 `margin-top` / `align-self` / `padding` 假装对齐：

  ```css
  .field__row {
      display: flex;
      flex-wrap: wrap;
      align-items: center;
      gap: var(--g-space-2);
  }
  .field__row .btn {
      flex: 0 0 auto;
      height: var(--g-ctl-h);            /* 与输入框同高 */
      border-radius: var(--g-radius-sm); /* 与输入框同圆角 */
  }
  ```

  验收：把并排的两个控件一起框进选区截图，边框上下缘必须落在同一像素行上；1440 与 390 各看一次。`.btn--small` 只用于卡头、表格行内这类不跟输入框并排的位置。
- 工具栏只放筛选时，控件靠左、按钮 `flex:none`，剩余空间留白；不要把搜索框 `flex:1` 撑满，也不要把下拉写成 `width:100%`。只有需要「搜索 + 右侧动作」时才用 `margin-left:auto` 把动作推到右边。
- ≤782px 工具栏可以换行，搜索/下拉可以各占一整行（此时 `width:100%` 是允许的），但必须一控件一行、页面不横向溢出；勾选框仍是 18px、开关仍是 38×22。
- 勾选框的外层 `label.check` 可以是整行可点区域，但勾选框本体固定 18×18（开关 38×22），文字靠左，不要用 `justify-content:space-between` 把框和文字拉到两端。
- 多选组（格式/尺寸 chip）用独立的 `grid` 容器：桌面 4 列 `minmax(0,1fr)`、≤500px 改 2 列；chip 等宽、`min-height:40px`，勾选框 18×18；说明文字放 grid 外的 notes 块，不参与列宽计算。
- 控件宽度要和内容匹配：数字/颜色/端口短，URL/路径长；同组字段宽度不一致时用网格列对齐，不要用空格或固定 margin 凑。下拉选项过长时用省略号或 `title` 提示，不要靠不断加宽下拉解决，筛选下拉保持 180px 上限。
- 新增控件先选类型再定宽；没有合适类型时用 `custom`，不要在页面里再写一条 `width:100%` 然后靠 `max-width` 一页页补，宽度上限优先加在公共容器/组件上。
- 缩略图/图标选择器不要做成大图方块（96×96 图 + 竖排文字会把整行撑到 150px，右侧输入框被顶到卡顶）。做成与输入框同规格的 chip：高 `--g-ctl-h`、同边框、同圆角、同 inset 高光，缩略图 ≤28×28，「选择图标」文字横排，与右侧输入框底边对齐；单列时 `justify-self: start` 保持内容宽。
- `button` 上不要只靠 `hidden` 属性做显示切换：组件里的 `display: inline-flex` 会盖掉浏览器默认的 `[hidden] { display: none }`，按钮会留在页面上继续占高。用 `hidden` 时配套写 `.btn[hidden] { display: none }`（1.27.3 已加在 `components.css`）。

## 11. 浏览器验证流程

目标：一次加载拿到尽量多的事实，只对真实用户路径做最终验收；不要把每个假设都变成一次整页重载。

- 先静态后浏览器：`php -l`、`node --check`、CSS 花括号计数、`git diff --check` 全过后再开浏览器。同一批改动只重新加载一次（必要时带一次 cache-bust 参数），后续探针复用同一页面，不要每改一个值就刷新。
- 先隔离后流程：怀疑某个 CSS/JS 状态导致问题时，先用一次 `browser_evaluate` 在当前页面里切换/还原可疑状态，确认机制；机制确认后再走真实点击。隔离探针只用于定位，不作为最终验收。
- 最终验收至少有一次真实点击：定位元素优先 `browser_find`，需要整体结构时才 `browser_snapshot`；每次操作后重新取 ref，再用 `browser_click`。`element.click()` 不会移动焦点，滚动/焦点问题很容易被测成假通过或假失败；只能用 evaluate 时，先 `focus({ preventScroll: true })`，并把它当辅助证据。
- 一次 evaluate 批量取指标：同一次调用里返回打开前/打开中/关闭后的 `scrollY`、`document.activeElement`、dialog 是否存在、body/html 内联样式、关键元素的 `getBoundingClientRect()`、`scrollWidth/clientWidth`。不要为每个数值单独往返。
- 视口切换用 `browser_resize`，复用当前页面，不重新导航；只有服务端按宽度/UA 输出不同 HTML 或需要清缓存时才刷新。切换后等一帧再量布局。
- 在问题发生的状态验证：滚动/焦点问题先把页面滚到非零位置（如 600）并让触发元素在视口内；在顶部测等于没测。移动端问题在 390 复现，不要只在 1440 推断。
- 等真实就绪信号：AJAX 表格等 `tbody tr` 数量或目标选择器出现，不要用固定 `setTimeout(2200)` 赌加载；需要动画结束时等 `transitionend` 或两次 `requestAnimationFrame`。
- 截图和 console 只收尾各做一次：只有布局有歧义、需要给用户看结果时才截最终态；console 在完整流程结束后查一次。中间态不截图、不逐条打印。
- 验证范围按第 8 节的宽度规则选择；纯视觉小修不机械跑七宽度/全路由，涉及响应式或共享样式才加宽覆盖。
- 文档同步放在代码稳定后：一次改完对应条目和自检项，不在调试过程中反复改文档。

## 13. 新功能页面开发清单

这一节把 2026-11 那轮改版踩过的坑收成可执行步骤。**按顺序做，每步都有可验收的判据**；跳过其中任何一条，都会以「加载时闪一下」「保存后跳顶部」「弹窗关不掉」的形式回来。

### 13.1 接入前：先把数据契约定下来

1. **页面 id 决定一切**：`Registry` 里的 tab id 同时是 `assets/ui/pages/{page}.js` 的文件名、`data-sakura-page` 的值、以及 `Layout::PAGES` 的键（经 `layout_for_page()` 映射）。定错之后 CSS 作用域、资源和布局全部对不上。
2. **有卡片的页面**：在 `Layout::PAGES` 补一条 `order` + `cards`（每张卡 `array( 行, 列, 跨列数 )`）；若页面 id 与布局 id 不同，在 `Layout::layout_for_page()` 补别名（如 `files-zibll` → `files-space`）。漏了不会报错，卡片会退化成组件默认宽度。
3. **新增一张卡**：同样在 `Layout::PAGES` 的 `order` 与 `cards` 里补条目。代码里**只有 `Layout::PAGES` 这一张表**（没有 `DEFAULT_LAYOUT`）。漏了不会报错：`Layout::card()` 返回 null，`UI::card()` 退到组件默认——`wide` 卡占满 12 列（`array( 0, 1, 12 )`，行交给 CSS），非 wide 卡则完全不输出位置变量、交给 CSS 自动放置，于是它不会出现在你期望的读写顺序里。需要临时指定时可用 `UI::card()` 的 `grid_column => array( 列, 跨列 )`（行同样交给 CSS），但常态应写进 `PAGES`。

### 13.2 写视图：用组件，不要手写骨架

- 页面 `UI::page()`、卡片 `UI::card()`、字段 `UI::field()`。**不要手写 `section.card > .card__head > .card__body`**，也不要在视图里重复 nonce、卡片标记和保存按钮。
- 卡片是**一个独立表单**：`UI::card( array( 'form' => array( ... ), 'save' => '保存设置' ), $body )`。不要多卡共享一个表单，也不要整页保存条。卡片内容只由本卡保存结果决定时加 `'inplace' => true`（§4.1），省掉一次整页往返；同页别处会显示派生读数时不要加。
- 需要反馈时按 5.1 的表选通道：**动作结果用 `UI::modal()`**、持续状态用 `UI::alert()` / `UI::notice()`、AJAX 小动作用 `admin.ui.toast()`。
- 新文案一律 `__()` 后塞进 `Page_Assets::set_data()`；JS 不内嵌未翻译中文。

### 13.3 加样式：只写令牌，不写新色

- 颜色只用 `tokens.css` 的 `--g-*` / `--sakura-*`。**不要新增第二种粉或第二种红**；需要多档色块就用 `--g-sakura-1..4`。
- 进度条用 `.progress` + `.progress__bar`（已带 `display:block`）。**自写进度条若换成行内元素，`width` 会被忽略、条完全不可见**——统计页曾经整条空白。
- 卡片底色与角落泛光分开写：`background-color` 放令牌、`background-image` 放 `--g-card-bloom`，否则系统设置里的自定义卡片色会被盖掉。

### 13.4 布局与滚动：这几条不满足就等于没做完

这是本轮回归最集中的地方，逐条都是实测出来的：

| 判据 | 怎么验 |
| --- | --- |
| 加载不闪、卡片不延迟 | 卡片 `visibility` 全为 `visible`；卡片 `style` 只有三个 `--g-card-*` 位置变量；加载 1s 内 `layout-shift` < 0.1 且卡片 `top` 不变 |
| 保存不跳顶部 | 滚到卡片保存条附近点保存，弹窗出现那一帧 `body.style.top` 已等于原 `scrollY`，关闭后位置误差 0 |
| 弹窗不改位置 | 深位置（如 `scrollY=1500`）用 X / 按钮 / Esc / 遮罩四种方式关闭，`scrollY` 均回到原值；焦点回触发元素但**不把页面滚进视野** |
| 页面不横溢 | `document.documentElement.scrollWidth === clientWidth`（1440 / 390 / 320 各测） |
| console 干净 | 无 error；特别注意 SVG 的 `width` / `height` 必须是单个数字，写成 `"16 16"` 会报 `Expected length` |

**机制备忘**（改之前先读，别重新发明）：

- 提示弹窗**不锁滚动、不加遮罩**，页面照常滚动和点击；确认弹窗与媒体预览用的是原生 `<dialog>`，`::backdrop` 只铺色调、不加模糊。不要为了「更专注」再给提示弹窗补遮罩或滚动锁——那正是闪屏的来源。
- 保存往返（POST → 302 → 新文档）要把 `路径|page + scrollY` 存进 `sessionStorage.sakuraAdminSaveScroll`，**在自动弹窗打开之前恢复**；screen key 不含 `t`（部分 saver 重定向回来不带 tab）。
- **不要再引入任何"加载后用 JS 改布局"的机制**。1.27 之前有过一版拖拽引擎：它把卡片改成绝对定位并重写文档高度，导致长页面跳动、卡片晚一帧出现、以及首屏隐藏规则误命中 `.card-grid` 而整页空白两秒。服务端确定的静态位置从根上消除了这三类问题。

## 14. 视觉方向 V2：樱前线（Sakura Front）

> **状态：设计定稿、代码未落地**（2026-11-19）。唯一视觉参考是 `docs/设计稿/s3-sync-center-sakura.html`（S3 同步中心整页 + 删除确认弹窗，单文件、零外链）。其余页面按这套语言推导，不自创第二套皮肤。

### 14.1 设计思路

概念叫「樱前线」：日本把樱花自南向北开放的等值线叫**桜前線**。同步中心的「本地媒体 → 云端对象 → 索引」三条线在数据上本来就是一条推进线，于是把它画成一条串起三个站点的花前线，花瓣沿线飘落——**数据自己开花，界面只讲「推进到哪一站」**，而不是再摆一排 KPI 卡片。页面标题下面那句「樱前线已经过境」是同一句话的文学说法：三条线对齐时，锋线已经走过去了。

三条主张，也是取舍标准：

1. **颜色只做两件事**：樱花（品牌与强调）与状态（成功/警告/错误）。装饰色永远不承载文字、也不表达状态。
2. **形状来自纸与花瓣**：卡片是和纸（细边框、笔记横线、角上一段和纸胶带），页签是花瓣贴纸，进度条是一罐汽水，弹窗是便签。圆角大、阴影软、边框细，没有一处硬直角。
3. **每页只热闹一处**：会动、会发光的主角只能有一个（同步中心是 hero 的花前线，任务中心卡片是那条冒泡的进度条），其余安静。想加第二处常驻循环动画，先删掉现有的。

为什么不走「贴图二次元」：插画会被现实内容挤变形、会过时、会拖慢首屏。所以只保留一个吉祥物（粉色小鲸鱼，只出现在弹窗里），其余全部用几何花瓣与留白表达。

- 白字只能压在 `--g-accent` / `--g-accent-hover` / `--g-ok` / `--g-warn` / `--g-bad` 与 `--g-ink` 上；压在任何 `--g-petal-*`、`--g-sun`、`--g-mint` 上都算不合格。淡粉底 `--g-brand-petal`（`#FFAACA`）上**永远不要白字**（1.77:1）；要浅底就换墨色：`--g-ink` 8.07:1、`--g-ink-soft` 6.38:1、`--g-accent-hover` 3.92:1（只够做徽标白底上的字，不够直接压粉底）。品牌瓦片是「淡底白图」的唯一例外，而且例外被限死在瓦片本身：`--g-brand-ink`（`#FFFFFF`）压 `--g-brand-petal` 只有 1.77:1，所以瓦片内只许放那一枚 18px 的装饰图形，**不得放字**；对象存储「使用中」配置卡是淡粉底承载文字的授权先例，靠把整块文字换成墨色成立，不要复制成「淡粉底 + 白字」。
- 开关轨道只承载位置、不承载文字：两态都由开发者指定为浅色（米白 / 樱花淡粉 1.77:1），状态靠**旋钮位置 + 色相**表达，所以轨道必须有 1px 内环、旋钮必须有发丝边和投影；旁边的说明文字走 `.check__text` 的常规墨色，不要把状态写成轨道里的字。

- 柱状图与进度条按「同一色相由深到浅」用 `--g-sakura-1..4`；donut 例外，必须用四个可区分的色相（见 §2 的说明），但饱和度上限仍是 `--g-petal-3` / `--g-sky` / `--g-sun` 这一档，不允许出现霓虹色或第二个品牌色。**唯一的交通灯**是环境评分条：`--g-score-ok` / `--g-score-warn` / `--g-score-bad` 只做**条形填充**（≥80 / 60–79 / <60 三档），旁边那个分数是文字，必须改用加深过的 `--g-ok` / `--g-warn` / `--g-bad`（6.3 / 5.3 / 6.4:1），不能直接拿填充色写字——满值只有 1.5–2.3:1。

### 14.4.1 滚动容器里的悬浮抬升

任何 `overflow: auto/scroll` 的条（页签条、窄屏模块导航）都要给「抬升 + 投影」留出内边距，否则容器会把它裁掉：

```css
.sakura-tabs {
	overflow-x: auto;
	overflow-y: hidden;          /* 滚动容器纵向必然是 auto，显式写出来提醒自己 */
	padding: 5px var(--g-gutter) 9px;   /* 上：1px 抬升 + 4px 向上投影；下：2px 偏移 + 6px 模糊 */
	margin: 11px auto -9px;      /* 视觉间距仍为 16px，占位高度与改动前一致 */
}
```

改**任何**滚动条的上下内边距时，都要同步改 `margin-block` 的负值，否则页面会整体上下漂移几像素。

### 14.5 动效

- **进场只允许一次**：hero 的花前线用 `stroke-dashoffset` 1.2s 画入，之后不再动；其余元素不做 fade-and-slide 入场。
- **进度条**：`IntersectionObserver`（阈值 0.35）触发宽度生长 1.15s `cubic-bezier(.22,.61,.36,1)`；气泡与泡沫是常驻 CSS 动画；到 100% 不额外庆祝。
- **弹窗**（2026-11-20 起）：进场 `240ms cubic-bezier(.16,1,.3,1)`，`translateY(8px) scale(.96) → 0/1` + 淡入；出场 `140ms cubic-bezier(.4,0,1,1)`，继续往上收（`translateY(-4px) scale(.985)`）——方向一致才不会像被抽走。关闭必须走 `closeDialog()`：加 `.is-closing`、听 `animationend`、再 `dialog.close()`，并留 220ms 兜底定时器（后台标签页收不到 `animationend`，否则卡片会赖在屏幕上）。遮罩只做「这里不是正文」：`rgba(74,43,58,.14)` + `blur(3px)`，不再压黑整页。
- **禁**：hover 缩放卡片、滚动视差、逐段 fade-in、超过两处常驻循环、`transition: all`。
- `prefers-reduced-motion: reduce`：划入动画直接落位，气泡与泡沫 `display:none`，印章与花瓣静止。
- 性能预算：新增 JS ≤ 1.5KB（IO + 气泡生成），CSS 增量 ≤ 6KB gzip（当前三件套 gzip 16.7KB）。

### 14.7 与 §1 旧禁令的关系

- 「不许放樱花 SVG」修订为：允许**内置几何 SVG**（花瓣、印章、小鲸鱼），统一放 `assets/ui/icons/*.svg`。两种落地方式：① 页面内联——`Shell::mark_svg()` 读文件后原样 echo（`.brand-mark` 的图标就是这样），或用 `<svg><use href="#…"></use></svg>` 引用 sprite 里的 `<symbol>`；② 遮罩——`mask-image: url(icons/*.svg)` + `background-color: currentColor`，用于必须跟随外部状态配色的地方（左侧菜单图标）。仍然禁止照片、外链图、位图背景，以及每个页面各画一套插画。
- **同一张图只存一份。** 品牌图标 `assets/ui/icons/sakura-mark.svg` 同时供顶栏 `.brand-mark` 内联与左侧菜单图标遮罩使用，不要在 PHP 里另存一份 path 数据——两边一旦各存一份就会漂移。
- **前台内联 SVG 必须用 CSS 给尺寸。** zibll 主题带一条全局规则 `svg{width:1em;height:1em;vertical-align:-.15em;fill:currentColor;overflow:hidden}`，CSS 压过 `<svg width="38" height="38">` 属性——在前台（用户中心 Tab、编辑器面板）写属性等于没写。`assets/userfiles.js` 的小鲸鱼曾是 38px，实际只剩一个字号的体积（约 13px），缩在弹窗标题旁像颗色斑。`assets/userfiles.css` / `assets/editor-picker.css` 里每个内联 SVG 都要有成对的 `width`/`height` 规则（`.sufm-icon`、`.sufm-folder-art svg`、`.sufm-editor-drop__icon svg` 都是这么写的）。2026-11-21 修弹窗吉祥物时补的是「36×36 圆角 10px 的 `--sufm-pink-soft` 徽章底板 + 30px 图形」，与「容量详情」的 `.sufm-capacity-mark` 同一套规格。
- 「唯一强调色 #9d3452」修订为 `--g-accent: #C7335B`（白字 5.18:1），品牌粉降级为装饰令牌。
- 其余规则（颜色只用令牌、只写 `assets/ui/`、卡片位置走自定义属性、不用 `!important`）一条不放松。
- **范围**：V2 只覆盖插件后台页面（`assets/ui/`）。媒体库的 `assets/ui/wp-media/*.css` 与前台/编辑器面板的 `assets/editor-picker.{css,js}` 这一轮继续用 V1 令牌，两边出现观感差异是预期内的；将来要统一时按 P4 单独做。
