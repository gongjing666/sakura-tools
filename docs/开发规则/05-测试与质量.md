# 05 测试与质量

三道关：**PHPUnit → PHPStan → PHPCS**；另有 `composer lint:compat` 单独守 PHP 版本边界（8.2 语法下限 / 8.4 生产运行时）。本页写清楚每道关检查什么、红线在哪、报错怎么处理。

## 1. 本地命令

```bash
composer install      # 首次
composer test         # PHPUnit
composer phpstan      # PHPStan level 5
composer lint:strict  # PHPCS，warning 也算失败
composer lint:compat  # PHPCompatibility，PHP 版本边界（8.2 下限 / 8.4 生产）
composer lint         # PHPCS，忽略 warning 的退出码
composer lint:fix     # phpcbf 自动修
```

**本机 `php` 默认指向面板的 8.2**，那个 build 的 `disable_functions` 禁掉了 `symlink` / `shell_exec` / `putenv` / `proc_open`：PHPUnit 会报 `Call to undefined function symlink()`，PHPCS 直接在 `Generic.PHP.Syntax` 里 fatal，PHPStan 也会死在 XdebugHandler。跑测试前先把 8.4 放进 PATH：`export PATH=/www/server/php/84/bin:$PATH`（实测 `PHP 8.4.28`，`putenv` 等函数可用）。

基线（2026-11-24 实测，PHP 8.4.28）：`903 tests, 3831 assertions, 6 skipped`，PHPStan `[OK] No errors`，PHPCS 0 error / 0 warning，PHPCompatibility 0 error / 0 warning。

依赖：PHPUnit 10.5、PHPStan 2.x（+ szepeviktor/phpstan-wordpress）、WPCS 3.2、PHP_CodeSniffer 3.x。要求 **PHP 8.2+**；PHP 版本兼容口径与 8.4 弃用清单见 [13-PHP代码规范](13-PHP代码规范.md)。

## 2. PHPUnit

### 引导不是 WordPress

`phpunit.xml.dist` 指向 `tests/bootstrap.php`，那是一个**手写的最小 WordPress shim**：定义 `ABSPATH`、`DAY_IN_SECONDS`、`KB_IN_BYTES` / `MB_IN_BYTES` / `GB_IN_BYTES`、`MINUTE_IN_SECONDS` / `HOUR_IN_SECONDS`，并手写 `class WP_Error`。

所以：

- 测试里能用的 WP 函数只有 shim 里桩过的那些；
- **要用新的 WP 函数，先在 `tests/bootstrap.php` 里补桩**，否则会 `Call to undefined function`；
- 不要试图在测试里启动真的 WordPress——那会让 620 多个测试从 1.4 秒变成分钟级。

### 目录

```
tests/
  bootstrap.php        最小 WP shim
  XxxTest.php          90+ 个顶层测试
  Admin/               后台渲染相关
  Services/            服务编排
  Thumbnail/           缩略图
```

### 写测试的优先级

| 代码 | 该不该配测试 |
|---|---|
| 纯函数 / 值对象 | 必须 |
| 服务类的分支与错误路径 | 必须 |
| Schema / 版本判定 | 必须 |
| 渲染输出的关键结构（有无某 class、表单标记） | 建议 |
| 纯样式 | 不测（用浏览器验收） |

### 断言钩子面

`Hook_Loader` 暴露 `actions()` / `filters()` 就是为了这个：

```php
$hooks  = new Hook_Loader();
$module = new My_Module( $service );
$module->register_hooks( $hooks );

$this->assertArrayHasKey( 'admin_init', $hooks->actions() );
```

这也解释了 `Module` 契约为什么禁止在构造函数里挂钩子——**钩子面可以在不启动 WordPress 的情况下被检查**。

### 注意

- `tests/bootstrap.php` 里手写的 `WP_Error` 只实现插件用到的方法；用新方法前先看有没有；
- 有 6 个 skipped，是环境相关的（Imagick/GD 缺失时跳过），**不要为了凑绿而删 skip**。
- `has_action` / `did_action` 有桩（`Support\Profiler` 用），但 `did_action` 是**累计计数**：测试里不要清空 `$GLOBALS['sakura_test_actions']` 来伪造「新请求」，那只会让 `did_action` 归零。参照 `tests/ProfilerTest.php` 的写法——先记下已发钩子数，事后比数量。

## 3. PHPStan

配置在 `phpstan.neon`：

- `level: 5`
- `paths: sakura-tools.php, uninstall.php, includes, src`
- `bootstrapFiles: stubs/phpstan-bootstrap.php`、`scanFiles: stubs/phpstan-plugin-dependencies.php`
- `treatPhpDocTypesAsCertain: false`
- **`reportUnmatchedIgnoredErrors: true`**

最后一条最容易被忽略，配置里的注释写明了理由：

> Ignoring a pattern that no longer matches is itself an error: it means the code moved and the note below became a lie.

也就是说：**代码改了位置、ignoreErrors 的正则不再命中，PHPStan 会报错**。这不是找麻烦——它在提醒你那条豁免已经过期，要么删掉、要么更新说明。

### 三条豁免及理由

| 模式 | 范围 | 理由 |
|---|---|---|
| `Variable \$(entry_status\|files_enabled\|files_entry\|enabled) might not be defined` | `includes/views/*` | 视图模板变量由渲染方保证；转义与 i18n 由 PHPCS 兜底 |
| ZibPay / `zibpay_*` | `src/UserFiles/Services/Space_Store.php` | 类与函数在主题里，代码有 `class_exists` / `function_exists` 与 try/catch 兜底 |
| `Sakura\Vendor\GuzzleHttp\` | `src/S3/Object_Store.php` | 第三方预置副本，约 4 万行不扫 |

**新增豁免必须写理由**，并保证模式足够窄（限定 path，不要全仓库）。

### 视图模板的类型声明

模板顶部用 `@var` 逐条声明变量：

```php
/**
 * @var array<string,mixed> $report
 * @var array{gapX:int,gapY:int} $gaps
 */
```

PHPStan 靠它推断类型；漏了就会掉进上面那条豁免。

## 4. PHPCS

配置在 `phpcs.xml.dist`，基于 `WordPress-Extra`。

### 检查范围

`sakura-tools.php`、`uninstall.php`、`src/`、`includes/`。排除 `vendor/`、`node_modules/`、`assets/`、`tests/`、`languages/`、`docs/`。

`minimum_supported_wp_version=6.5`、`parallel=8`。

### 刻意关掉的 sniff

配置里成组关掉了「纯格式」类 sniff，注释解释：

> 项目自有风格与 WPCS 只在空白/对齐上不同，强行统一会产生约 1900 hunk 的无行为改动。

关掉的是：数组对齐与缩进、多语句同一行、`ScopeIndent`、函数调用签名、多行函数声明、控制结构签名、多余空白、双引号强制、PSR2 的类声明/命名空间/闭合花括号、PSR12 返回类型、`dirname` 现代化、数组尾逗号、控制结构空格、运算符空格、Yoda 条件、短三元、独立自增、文件名规则。

**结论：不要为了「合规」去重排对齐**——那类改动会被拒绝，而且制造巨大的无意义 diff。

### 前缀白名单

`WordPress.NamingConventions.PrefixAllGlobals` 允许：`sakura_imgopt`、`sakura_tools`、`sufm`、`sakura`、`Nboke`。排除 `includes/views/*`（模板局部变量不是全局）。

### 自定义能力

`WordPress.WP.Capabilities` 里登记了 6 个：`sufm_manage_media_folders`、`sufm_transfer_media_files`、`sufm_manage_own_files`、`sufm_request_delete_own_files`、`sufm_admin_delete_files`、`sufm_admin_review_deletions`。

新增能力要同时改这里，否则会报未登记。

### severity 0 的豁免

| sniff | 为什么关 |
|---|---|
| `DB.PreparedSQL.InterpolatedNotPrepared` / `.NotPrepared` | 表名一律来自 `Schema::table()`，值都走 `$wpdb->prepare()` |
| `Security.NonceVerification.Missing` / `.Recommended` | REST 走 `X-WP-Nonce`，不是表单 nonce |
| `WP.AlternativeFunctions` | 移动/复制文件本来就是本职 |
| `PHP.DiscouragedPHPFunctions` | base64 用于签名 |
| `PHP.NoSilencedErrors` | 文件系统探针用 `set_error_handler` 而非 `@` |
| `Generic.CodeAnalysis.UnusedFunctionParameter` | 接口兼容 |

当前基线是 **0 error / 0 warning**（2026-11-16 实测）。动态 SQL 的两类占位符误报已逐处加 `phpcs:ignore`，并在注释里写明不变量（占位符列表与参数数组来自同一个 ID 数组）；sniff 保持开启，真正数错参数仍会报。其余命名、文案与 cron 间隔 warning 已清理或按有意设计逐处豁免。

新增任何 warning 都当作 error。

### 版本兼容（PHPCompatibility）

除了 `phpcs.xml.dist`（WP 惯例与安全），还有第二套独立规则集 `phpcs-compat.xml.dist`，它只管一件事：**这段代码在 PHP 8.2–8.4 上会不会炸**。

- 扫描范围：`sakura-tools.php`、`uninstall.php`、`fast-search.php`、`src/`、`includes/`；排除 `vendor/`、`node_modules/`、`assets/`、`tests/`、`docs/`。
- 版本口径 `testVersion 8.2-8.4`：**8.2 是最低语法（写到 8.3/8.4 才有的话，8.2 站点直接白屏），8.4 是生产运行时（弃用会进 `debug.log`）**。
- 跑法：`composer lint:compat`；基线 **0 error / 0 warning**（2026-11-24 实测）。接入时抓到 7 处 `fputcsv` 没传 `$escape`，已全部显式补全五个参数（分隔符、包裹符、escape 传空串，即 RFC 4180 与 PHP 9 的默认值）。
- 依赖装不上先看 Composer 版本：本机 `/usr/bin/composer` 是 2.0.14，`composer-plugin-api` 不满足 dealerdirect 的 `^2.2`，要用 Composer 2.11 的 phar 安装。

为什么锁 `PHPCompatibility` 10.0.0-alpha2、PHPStan 侧的 `phpVersion: 80200` 怎么配、以及过渡期的 grep 自查，见 [13-PHP代码规范](13-PHP代码规范.md) §6。

### 提交前

`composer lint:strict` 与 `composer lint:compat` 都必须无 error、无 warning；新增的任何一条都当作 error 处理（对照 `--report=source` 看是哪一类）。

## 5. CI

| workflow | 触发 | 做什么 |
|---|---|---|
| `tests.yml` | push main/master、PR | PHP `8.2` / `8.3` / `8.4` 矩阵跑 `composer test` |
| `phpstan.yml` | push main/master、PR | PHP 8.2 跑 `phpstan analyse --error-format=github` |
| `release.yml` | push main 且改动 `sakura-tools.php` / `readme.txt` / `bin/build-plugin-zip.sh` / 自身 | 见 [06-发布流程.md](06-发布流程.md) |

## 6. 手工验收（文档管不到的部分）

自动化测不到的三件事，靠浏览器：

1. **视觉**：1440 与 390 两个宽度各看一遍；改共享层时覆盖全部后台路由。判据见 [03-后台UI.md](03-后台UI.md) 第 11、12 节。
2. **交互**：保存一次、开一次弹窗、关一次弹窗——至少走一遍完整路径。
3. **console**：不能有 error。特别注意 SVG 的 `width` / `height` 必须是单个数字，写成 `"16 16"` 会报 `Expected length`。

### 验证环境

**代码改动必须测，纯文档改动不测。** 改 PHP / JS / CSS 时 §1–§4 的本地命令一轮不落（`composer test` / `composer phpstan` / `composer lint:strict` / `php -l` / `node --check` / `git diff --check`）。

上面三件事（视觉、交互、console）需要真实 WordPress 与浏览器，跑在**开发者指定的环境**：他说了就在他指定的环境看；没说就不要自行部署到实验站或生产站，把要看的点写进交付说明交给他。

**当前实验站（2026-11-24 起）：** `https://demo.77il.cn`，宝塔面板本机站点，目录 `/www/wwwroot/demo.77il.cn`；PHP 8.4.28 + MariaDB 12.3.2（与生产 `www.nboke.com` 同版本），WordPress 7.1.5，DB `demo`、前缀 `wp_`，主题子比已授权，管理员 `yexu`（密码不写进仓库）。`WP_DEBUG` / `WP_DEBUG_LOG` 都开着，弃用与警告会同时显示在页面上并写进 `wp-content/debug.log`——验收 PHP 版本兼容时正好看这里。插件按**整目录拷贝**同步（不是软链），站上已装 `1.28.8-beta-46`（25 张表已建，`wp sakura-sync` 可用）。同步命令与「必须带上 `assets/ui/dist/`（排掉它会让 React 页卡在骨架屏）」的说明见 `AGENTS.md` §6 的实验站条目。旧的内置服务器站 `/root/sio-e2e` 已于 2026-11-24 连同 docker 容器与数据卷整体删除，备份在 `/root/backups/sio-e2e-20261124-1316/`，不再作为验收环境。

**在实验站改过设置要按原值还原，不要按默认值还原。** 功能测试经常会改选项（压缩模式、重命名规则、尺寸勾选、备份策略…），这些值多半是开发者自己调的，和 `DEFAULTS` 不一样。2026-11-24 就出过事故：测「上传文件重命名」时把 `rename_rule` 写成 `{date}-{time}-{rand}`、`rename_fixed` 写成空串来简化验证，收尾时又「按默认值还原」，把开发者设的 `{date}-{time}-{rand}-{fixed}` 与固定文本 `Sakura` 一起冲掉了，界面上看起来像是功能丢了。做法：动手前把要碰的 option 原样 dump 到 `/tmp/…json`（`Settings_Repository::all()` 或直接 `get_option()`），测完用同一份数据逐项写回并核对一次界面，别用「我记得默认是什么」当还原依据。

纯文档改动（只改 `.md`）整轮不测、连版本号都不动，直接 push `main` 同步 GitHub，见 [06-发布流程.md](06-发布流程.md) §1。

### 用 Query Monitor 看插件自身耗时

装 [Query Monitor](https://wordpress.org/plugins/query-monitor/) 后，`Support\Profiler` 的埋点会出现在顶部工具条的「计时」面板里，名字带 `Sakura ` 前缀。**面板默认是空的**——Query Monitor 自己一次也不发 `qm/start`，空面板是它的设计而不是故障；本项目在关键路径上调了 `Profiler`，所以只要插件在跑就有行。

验收时看这几点：

1. 打开任意一个后台页，顶部工具条的「计时」（Timings）徽标应 ≥ 1；
2. 面板里应有 `Sakura boot`、`Sakura modules`、`Sakura register hooks`、`Sakura admin page …`，其中 `boot` 带 `schema` / `hooks queued` 两个分段；
3. 传一张图，应多出 `Sakura upload process` / `Sakura upload subsizes`（启用 S3 时还有 `Sakura s3 upload`）；
4. 停用 Query Monitor 后页面行为不变（`Profiler::enabled()` 恒 false，`measure()` 退化成直接调用）。
5. 后台任意页面的「重复查询」面板里，**插件自己的查询必须为空**（先在「潜在问题来源」看清是主题 / WordPress 还是我们）。同一个请求里对同一张自定义表的探测与聚合只许查一次：`SHOW TABLES LIKE`、`latest_scan()`、账本聚合都要走实例或静态 memo，并在**每一个**写入点失效。已按这条修过三类：同步中心 `{prefix}sio_sync_scans`（`Index_Repository::latest_scan()`，见 [07-S3存储生命周期.md](07-S3存储生命周期.md) §9 V28l）、附件链接改写 `{prefix}sio_url_rewrites`（`Url_Rewrite_Repository::runs()`，见 07 §9 V28m）、文件空间「子比专属」`{prefix}sufm_space_grants`（`Space_Store::grants_table_exists()`，共享给 `Space_Rules`，`1.28.7-beta-16`）。

「存在冲突的 db.php」红字是另一回事：`wp-content/db.php` 必须是**指向 `plugins/query-monitor/wp-content/db.php` 的符号链接**，不能是拷贝，否则 Query Monitor 加载不了 `QM_DB`，「组件」「受影响行」两列也会一起消失。`wp qm db-dropin` 或重新激活插件可重建它。

这个 drop-in 也不能让插件的远端写入失效：`Remote_Operation_Guard` 曾在检测到 `db.php` 时直接拒绝一切远端删除/上传（`1.28.7-beta-16` 及以前，表现为「只删了本地、云端没删」），`1.28.7-beta-17` 起改为比对两侧数据库身份（`DATABASE()` + `@@server_id`），同库同服务器的 QM drop-in 放行、确实把查询路由到别处的 drop-in 仍然拒绝，见 [07-S3存储生命周期.md](07-S3存储生命周期.md) §9 V28n。

## 7. 常见失败对照

| 报错 | 原因 | 修法 |
|---|---|---|
| `Call to undefined function xxx()` | shim 里没桩 | 在 `tests/bootstrap.php` 补 |
| PHPStan `Ignored error pattern ... was not matched` | 代码移动导致豁免失效 | 更新 `phpstan.neon` 的 path 或删掉该条 |
| PHPCS `PrefixAllGlobals` | 用了白名单外的前缀 | 改名 |
| PHPCS `NonceVerification` 在 REST 里 | 走了表单 nonce 检查 | REST 用 `X-WP-Nonce`，该 sniff 已全局关闭，若仍报说明在别处 |
| PHPCS 大量对齐 error | 用了格式化工具 | 这些 sniff 已关闭；检查是否误跑了 `phpcbf` 全仓库 |
| 测试在本地过、CI 挂 | PHP 版本差异 | CI 跑 8.2/8.3/8.4，本地至少跑一次 8.2 |
