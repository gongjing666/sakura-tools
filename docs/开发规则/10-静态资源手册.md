# 10 静态资源手册（CSS / JS）

给**要手动调外观的开发者**用的地图：哪个文件管哪块界面、什么时候加载、改哪里会波及全局、以及怎么覆盖才不会被下次更新冲掉。

本文只讲「文件与加载」，**不重复设计规则**：颜色语义、间距刻度、控件规格、验收清单在 [03-后台UI](03-后台UI.md)；数据与 option 在 [04-数据与存储](04-数据与存储.md)。

> 行数、字节数会随开发变化，表里只用来量级参考。**1.29.0 起全部后台页面的内容区都是 React 岛**；`assets/ui/js/pages/*.js` 只在对应 bundle 不可读时作为兜底，不是活跃实现。要最新数字：
> `find assets -name '*.css' -o -name '*.js' | xargs wc -l | sort -n | tail -20`

## 1. 一分钟定位

```bash
# 看到一个类名，想知道它在哪个文件、哪一行
rg -n "card__title" assets/ui

# 想改一个颜色，先确认它是不是令牌
rg -n -- "--g-accent|--g-brand-petal|--sufm-pink" assets/ui/tokens.css assets/userfiles.css

# 不知道当前页面属于哪个作用域
#   浏览器控制台：
document.querySelector('.sakura-admin').dataset.sakuraPage   // 例如 "storage-connection"
```

## 3. 后台加载管线

**只有一个入口**：`src/Admin/Page_Assets.php::enqueue( $page )`（`:47`）。它的调用链是

```
admin_enqueue_scripts
  └─ 各模块的 enqueue_admin_assets( $hook )
       └─ if ( ! Registry::on( 'storage' ) ) return;   // 模块级页面判断
            └─ Assets::enqueue_page()
                 └─ Page_Assets::enqueue( Route::current_page() )   // 形如 "storage-connection"
```

加载顺序（也是依赖顺序）：

| # | handle | 文件 | 条件 |
|---|---|---|---|
| 1 | `sakura-admin-tokens` | `assets/ui/tokens.css` | 永远 |
| 2 | `sakura-admin-base` | `assets/ui/base.css` | 永远 |
| 3 | `sakura-admin-components` | `assets/ui/components.css` | 永远 |
| 4 | `sakura-admin-page-{module}` | `assets/ui/pages/{module}.css` | 文件存在（可选；单页模块可以没有） |
| 5 | `sakura-admin-page-{page}` | `assets/ui/pages/{page}.css` | 文件存在（页签级补充，如 `storage-cost.css`） |
| 6 | `sakura-admin-core` → `-api` → `-ui` | `assets/ui/js/{core,api,ui}.js` | 永远，在页脚 |
| 7 | `sakura-admin-page-{page}` | `assets/ui/js/pages/{page}.js` | 文件存在，且该页没有已就位的 React 岛（见 3.3） |

`module` 取自页面 id 的第一段（`storage-connection` → `storage`），所以**新增页签不需要改 PHP**：放一个同名 CSS/JS 就会被自动带上。

模块级 CSS 是**可选**的：只有它真的入队时，页签级 CSS 才把 `sakura-admin-page-{module}` 作为依赖，否则只依赖 `sakura-admin-components`。所以像「子比增强」这种只有一个页签、只有 `zibll-performance.css` 的模块不会产生「依赖项尚未注册」的 `WP_Styles::add` 警告（Query Monitor 会把它报成样式依赖错误）。

页面 id 的形态是 `{module}-{tab}`（`src/Admin/Route.php:31` `page_id()`），也就是 `<div class="sakura-admin" data-sakura-page="storage-connection">` 里的那个值。它同时决定：加载哪份页面 CSS/JS、以及 CSS 里 `[data-sakura-page="…"]` 的匹配。

### 3.1 内联的两处

- `sakura-admin-tokens` 上追加一段 `wp_add_inline_style`：`.sakura-admin{--g-grid-gap-x:..px;--g-grid-gap-y:..px;}`，值来自「系统设置 → 布局设置」。
- 页面根节点上追加 `style="…"`：`src/Admin/Appearance.php::inline_style()` 输出的 `--g-page-max`、`--g-card-border-width`、`--g-radius-card`、`--g-shadow-card`。**默认值不输出**，所以不配置时令牌说了算。

### 3.2 版本串与缓存

每个资源的 `?ver=` 由 `Page_Assets::group_version()`（`:190`）算：

```
SAKURA_TOOLS_VERSION . '.' . filemtime . '.' . 字节数      // 例：1.29.0.1795242531.77837
```

文件一改，URL 就变，浏览器和 CDN 自动取新的。**不需要手动清缓存**，也不要手写 `?ver=`。

但**不带 `?ver=` 的裸 URL 会被 CDN 边缘缓存 30 天**（实测 `eo-cache-status: HIT`、`cache-control: max-age=2592000`）。排查样式没生效时，别用裸 URL 下结论：

```bash
curl -sI "https://站点/wp-content/plugins/sakura-tools/assets/ui/components.css?ver=$(date +%s)" | head -3
```

前台（`.sufm` 系列）用的是另一套等价实现：`src/UserFiles/Support/Assets.php::version()`，格式相同。

### 3.3 岛页面不再加载旧页脚本

页签迁成 React 岛之后，页面主体由 `assets/ui/dist/{module}.js` 整块替换，`assets/ui/js/pages/{page}.js` 需要的挂载点基本都不存在了。但旧脚本**不会自己退出**：它在找不到 `[data-sakura-*-strings]` 时只是把配置当成空对象，接着照常跑完所有 `init*`，于是两套渲染共用的少数 id（例如 `#sakura-s3-test-connection`）会被绑定两次——点一次按钮发出两条请求，其中一条还带着空配置。

所以规则是：**岛 bundle 存在时，不再入队旧页脚本**；bundle 缺失时保留旧脚本，服务端渲染的兜底页仍然要它。

实现在 `Page_Assets`：

```php
private const ISLAND_BUNDLES = array(
    'image-rules'         => 'assets/ui/dist/image.js',
    'image-thumb'         => 'assets/ui/dist/image.js',
    'image-backup'        => 'assets/ui/dist/image.js',
    'image-stats'         => 'assets/ui/dist/image.js',
    'storage-connection'  => 'assets/ui/dist/storage.js',
    'storage-sync'        => 'assets/ui/dist/sync.js',
    'storage-deletes'     => 'assets/ui/dist/deletes.js',
    'storage-rewrite'     => 'assets/ui/dist/rewrite.js',
    'storage-cost'        => 'assets/ui/dist/cost.js',
    'files-settings'      => 'assets/ui/dist/files.js',
    'files-users'         => 'assets/ui/dist/files-users.js',
    'files-queue'         => 'assets/ui/dist/files-queue.js',
    'files-log'           => 'assets/ui/dist/files-log.js',
    'files-zibll'         => 'assets/ui/dist/zibll.js',
    'zibll-performance'   => 'assets/ui/dist/performance.js',
);
```

`enqueue()` 里第 7 行脚本的入队条件加 `&& ! self::island_owns( $page )`，`island_owns()` 同时判断「这个页面登记了 bundle」和「bundle 文件真的在」。新增一个岛页时，把 `{page} => assets/ui/dist/{module}.js` 加进这张表即可，**不要删旧脚本文件**——它是兜底路径。

1.29.0 起 15 个后台页面全部登记；`media-progress` 不是后台设置页，仍走 `assets/ui/js/pages/media-progress.js`。旧脚本的差别只在「有没有自守卫」：图片四页取不到挂载点会提前 `return`，同步中心等页会继续跑 `init*` 造成重复绑定。入队层的统一判断已经覆盖两类，不需要为每页写判据。

> 为什么不是「让旧脚本自己检测到岛就 return」：那要求每个页面脚本都维护一份判据，漏一个就复发；而且重复绑定发生时控制台不报错，只有抓网络才看得出。放在入队层是单点，且能统一处理。

## 4. 作用域、分层与特异性

```
:root                       tokens.css
.sakura-admin               base.css / components.css
.sakura-admin[data-sakura-page^="storage-"]    pages/storage.css
.sakura-admin[data-sakura-page="storage-cost"] pages/storage-cost.css
```

四条约定：

1. **一切选择器都从 `.sakura-admin` 起头**（`#adminmenu` 是唯一另一处根）。实测分布：`components.css` 448 条规则里 0 条带页面作用域，等于纯组件层；`base.css` 126 条里 21 条不带根，它们是 `@keyframes`、`@media` 包裹层，以及移动端底栏 `.sakura-nav-bar`（在 `.sakura-admin` 之外）。除此之外不要新增"裸"选择器。
2. **页面级规则加 `[data-sakura-page=…]`**，别在 `components.css` 里写只对某页成立的样式。反过来，一条规则如果三个页面都要，就不该留在 `pages/*.css`。
3. **新代码不写 `!important`**。要给新规则提权，加一层父选择器或 `:where()` 降低对手特异性即可。现有例外都带注释：后台只有 `pages/storage.css:220`（2 处，压子比主题的全局 `[disabled]{opacity:.6!important}`）与 `media-folders.css`（2 处，压 FileBird 工具栏）；前台 `userfiles.css` 10 处、`editor-picker.css` 18 处（隐藏主题元素、覆盖主题绝对定位、`prefers-reduced-motion` 兜底）。
4. **卡片位置不是 CSS 排的**。`src/Admin/Layout.php` 把 `grid-column` / `order` 直接内联到每张卡上，首屏即终态，没有拖拽引擎。改布局 → 改那张表，不要写 `:nth-child`。

命名的三件套：`block__element`、`block--variant`、`is-state`（`is-active` / `is-locked` / `is-empty` / `is-danger`）。

断点（`base.css` 为主，页面层有少量补充）：`782px`（WP 后台折叠线）、`1100px`、`900px`、`960px`、`600px`、`520px`、`500px`、`560px`，以及 `prefers-reduced-motion: reduce`。

| 装饰 | `--g-petal-1..3` `--g-sun` `--g-sky` `--g-sky-ink` `--g-mint` `--g-glass` `--g-petal-fall` | **只能填色或描边，永不承载文字** |
| 几何 | `--g-radius-card/-lg/-md/-sm/-xs/-pill` `--g-card-border-width` | |
| 排版 | `--g-font` `--g-font-mono` `--g-fs-body/-small/-meta/-eyebrow/-table/-h1/-h2/-h3` `--g-lh-body/-tight` | |
| 尺寸 | `--g-ctl-h` `--g-btn-h` `--g-btn-h-sm` `--g-gutter` `--g-page-max` `--g-card-pad-*` `--g-stack` `--g-space-1..6` `--g-grid-gap-x/y` | 控件宽度上限表在 03 的 §12 |

### 5.1 间距只许有一处真源

同一个视觉间距被两个选择器各写一个值时，谁赢取决于源码顺序和特异性——这正是 2026-11-23 那次「勾选框与文字在三个地方分别是 10px / 8px / 9px」的来源。修好后固定为：

- 勾选框、单选、开关与它旁边的文字：**只读 `--g-check-gap`（10px）**。`.check`、`.field__control > label`、`.check:has(> input.is-switch)` 三处都引用令牌，谁先谁后都不会变值；
- `.check:has(> input.is-switch)` 只负责 `align-items: center`（文字压开关的中线），**不再写 gap**——它的 gap 曾经是第三个数；
- 网格间距只有 `--g-grid-gap-x/y`；卡内竖向留白只有 `--g-stack`；控件高度只有 `--g-ctl-h`。要新加间距先用现成令牌，确实没有再加，并写进本表。
- **字段类型的通用表现只在 `components.css`**：`.field--w-fit`（控件按内容定宽）、`.field--limits`（行内限值行）、`.format-grid` / `.format-box`（多选方框）都是「字段种类」的样子，不属于某一页。它们一度只写在 `pages/image.css` 并带 `[data-sakura-page="image-rules"]` 限定，于是下一个页签要用时只能再复制一份。判断标准：**如果描述符只是 `type` 不同、页面逻辑没参与，就归共用层**；页面 CSS 只留本页独有（`page-savebar`、`field--rule` 这类）。这些规则的放置位置在基础输入规则之后（`--g-ctl-h` / `width:100%` 那一段之后），因为特异性相同时是后者取胜——放到前面会被 `width:100%` 顶掉，限值行三个数字框会从 80px 被撑到 129px。

### 5.2 DevTools 里「很多样式像是过期的」

在后台随手选中一个元素，样式面板里常有一大片被划掉的声明，这不是垃圾文件，逐条对应三种正常现象：

1. **层叠**：`tokens → base → components → pages/{module} → pages/{page}` 五层都写同名选择器时，只有最后一层赢，前面的仍要保留（别的页面没有后者）；
2. **运行期拼出来的类**：`alert--ok`、`toast--warn`、`badge--{tone}`、`kpi--score-{tone}`、`field--{type}`、`field--rule`、`.style-choice__visual--{style}` 都是 `'前缀--' + 变量` 拼的，源码里搜不到完整字符串，**不能靠 grep 判定为死代码**；
3. **WordPress 自带**：`#your-profile label`、`wp-menu-image`、`wp-has-current-submenu` 等不是本插件的规则。

真正该删的是「选择器里的类名在当前 PHP/JS 里一次都不出现、且不属于上述三类」的规则。判定方法（本次用的就是这个）：抽出 CSS 里所有类名 → 在 `src/`、`includes/`、`assets/ui/src/`、`assets/ui/js/` 的语料里做词级查找 → 把 `is-/has-/js-` 前缀与动态后缀排除后，剩下的才动手删。2026-11-23 按此删掉 7 条（`card--thumbs`、`sakura-imgopt-field-disabled`、`sakura-imgopt-sizing-note`、`sakura-thumb-evidence`、`queue-empty`、`quota-hint`、`profile-toolbar`），视觉零变化。

对比度红线（改色前必须过，脚本化算一遍）：

- 白字只能压 `--g-accent` / `--g-accent-hover` / `--g-ok` / `--g-warn` / `--g-bad` / `--g-ink`。
- 淡粉 `--g-brand-petal` 上白字只有 **1.77:1**，必须换 `--g-ink`（8.07:1）或 `--g-ink-soft`（6.38:1）；`--g-muted` 只有 3.69:1，不合格。
- `--g-petal-2` 上 `--g-ink-soft` 5.32:1 可用，`--g-muted` 3.08:1 不行。

## 6. 想改外观的五种正规途径

按「改动面从小到大」排列，优先选最上面的。

### ① 后台设置（零代码）

「系统设置 → 布局设置」卡片里已经有四个旋钮：页面最大宽度（960–1920）、卡片边框宽度（0–6）、卡片圆角（0–40）、卡片阴影（默认/无/柔和/重）；另有卡片间距 X/Y。

它们写进 option `sakura_imgopt_ui_style` 与 `sakura_imgopt_layout_gaps`，再以**内联 CSS 变量**的形式落在 `.sakura-admin` 根节点上。所以：能在这里调的就别改代码。

### ② 只改令牌（一处改，全站生效）

适合「把粉色换一档」「圆角再小一点」。写在子主题或一个自建小插件里：

```php
add_action( 'admin_enqueue_scripts', function ( $hook ) {
	unset( $hook );

	if ( ! class_exists( '\Sakura\ImageOptimizer\Admin\Route' ) ) {
		return;
	}
	$page = \Sakura\ImageOptimizer\Admin\Route::current_page();
	if ( '' === $page ) {
		return; // 不在插件页，什么都不做
	}

	wp_register_style( 'my-sakura-tweak', get_stylesheet_directory_uri() . '/sakura-tweak.css', array( 'sakura-admin-components' ), '1' );
	wp_enqueue_style( 'my-sakura-tweak' );
}, 20 );
```

`sakura-tweak.css`：

```css
.sakura-admin {
	--g-accent: #b02a4f;
	--g-radius-card: 14px;
}
```

**声明依赖 `sakura-admin-components`** 是关键：它保证你的文件排在组件之后。仅改令牌时不需要任何 `!important`。

### ③ 覆盖某一个组件

```css
.sakura-admin .card__kicker { letter-spacing: .08em; }
.sakura-admin .btn--primary { border-radius: var(--g-radius-pill); }
```

特异性 `.sakura-admin .card__kicker`（0,2,0）已经压过插件里同样形态的规则；如果你要压的规则本身就带 `[data-sakura-page]`，**多带一层同样的限定**即可：

```css
.sakura-admin[data-sakura-page^="storage-"] .profile-card { box-shadow: none; }
```

### ④ 覆盖单页

页面 id 在根节点上，直接当选择器用：

```css
.sakura-admin[data-sakura-page="image-rules"] .rule-token { transform: none; }
```

页面 id 列表见 §2.1（`{module}-{tab}`），也可以运行时读 `document.querySelector('.sakura-admin').dataset.sakuraPage`。

### ⑤ 前台（子比主题）

前台的入口不是 CSS 变量覆盖，而是**主题变量**——`assets/userfiles.css` 第一段的 `--sufm-*` 全部 `var(--main-bg-color, …)` 这样派生自主题：

```css
.sufm {
	--sufm-pink: #f04494;      /* 想换主色，改这个比改 4683 行里的每一处省事 */
	--sufm-radius: 10px;
}
```

**不要改插件文件**：下次更新会覆盖，而且前台这套还有 `editor-picker.css` 那份 fork 要同步。

## 7. 前台样式（子比）的三个坑

1. **作用域是 `.sufm`**，不是 `.sakura-admin`。两者互不相干，后台的令牌在前台一律不存在。
2. **主题有全局 `svg{width:1em;height:1em;vertical-align:-.15em;fill:currentColor;overflow:hidden}`**。CSS 声明优先于 `<svg width="38">` 属性，所以前台所有内联 SVG **必须用 CSS 给尺寸**，例如 `.sufm .sufm-dialog-mascot svg { display:block; width:30px; height:30px }`。这就是「弹窗里的小鲸鱼缩成一个点」的成因。
3. **暗色主题是手动覆盖的**：`.dark-theme .sufm { … }`（`assets/userfiles.css:29` 起重新定义整套 `--sufm-*`）。新增前台组件时，暗色要在同一个块里补一次，否则深色主题下会是浅底白字。

另外两处前台样式各有自己的规矩：

- `assets/userfiles-space.css`：作用域 `#sufm-space-dialog`，**一个硬编码颜色都没有**，全部读主题变量；不要 `vw`（内容区宽度 = 视口 − 320px 侧栏 − 间隙）。
- `assets/editor-picker.css`：作用域 `#sufm-picker`，是 `userfiles.css` 的 fork，改一边记得同步另一边。

### 7.1 前台文件浏览器的交互契约（Windows 资源管理器的口径）

`/user/files` 的那套网格/列表按桌面资源管理器的习惯做，改交互前先对一遍：

| 操作 | 结果 |
|---|---|
| 单击 | 只选这一项（清掉其它），刷新底部批量条 |
| Ctrl/⌘ + 单击 | 加选/减选这一项 |
| Shift + 单击 | 从锚点到这一项连选（只增不减） |
| 双击 | 打开文件（新标签页） |
| 再点一次已选中的项（仅 `(hover: none)` 的触屏） | 打开 —— 触屏没有可靠的双击 |
| 右键未选中的项 | **先把它选中**，再弹它自己的菜单 |
| 右键已选中的项（选中数 > 1） | 弹批量菜单：已选 N 项 / 移动到 / 移到上一级 / 复制链接 / 取消选择 / 申请删除 |
| 右键空白处 | 新建文件夹 / 全选 / 刷新列表（有选中时多一项取消选择） |

两条实现约定：

- **选中表现是「整块颜色」，不是勾选框。** `.sufm-row.is-selected` 是淡粉底 + 左侧 2px 竖线，`.sufm-file-card.is-selected` 是淡粉底 + 粉色描边 + 粉字。勾选框仍然留在 DOM 里（Tab 能到、空格能切），但被 `clip-path: inset(50%)` 裁成 1px，焦点环挪到卡片上（`:has(.sufm-check:focus-visible)`）。**不要把勾选框重新画出来**，那就退回到旧观感了。
- **文件夹折叠是一个药丸**：`⌄ 子文件夹 · N · 收起/展开`。`.sufm-fold-verb` 的文案跟着 `aria-expanded` 换（`收起` ↔ `展开`），折叠状态存在 `localStorage` 的 `sufm_folders`。别只留一个 tooltip —— 用户不会去 hover 一个灰条。
- 触屏上容器都带 `touch-action: manipulation`，否则 iOS 会为了等双击把每次点击延后 300ms。
- **桌面头部第二行只允许让位，不允许撑开。** `≥1200px` 时 `.sufm-head` 是 `flex-wrap` 的两行布局，第二行只有两个 item：`.sufm-path`（面包屑）与 `.sufm-toolbar-main`（627px 的按钮组）。`path` 必须写 `flex: 1 1 0` + `min-width: 0`，**不能写 `flex: 1 1 auto`** —— 用 `auto` 时它的内容宽度（面包屑 + 「Shift 连选…」提示 + 计数）会先吃满整行，把按钮组挤到第三行，看起来就是「右侧一大块空白」。这个 bug 还会随视图切换跳动：列表↔网格会改变竖向滚动条（约 15px），跨过临界点就整行跳变，所以「管理员不出问题、普通账号出问题」。
  配套还有两条：`.sufm-path` 带 `container-type: inline-size`，提示用 `@container (max-width: 420px)` 隐藏（**按 path 自己的宽度判断，不是视口宽度** —— 主题有侧栏时内容列可能只有视口一半）；隐藏后提示文字挪到 `.sufm-path` 的 `title` 上，hover 仍能读到。

**编辑器里的面板（`#sufm-picker`）只差一条：双击是插入，不是打开。**

| 操作 | 用户中心 `/user/files` | 编辑器面板 `#sufm-picker` |
|---|---|---|
| 单击 | 选中 | 选中（相同） |
| Ctrl/⌘、Shift + 单击 | 加/减选、连选 | 相同 |
| 双击 | 新标签页打开文件 | **把文件插入正文**（TinyMCE 里落成 `<img>` / 视频块 / 下载卡片） |
| 右键已选中的多项 | 批量菜单（含申请删除） | 批量菜单（含**插入所选**，没有删除） |
| 右键空白处 | 新建文件夹 / 全选 / 刷新 | 相同 |
| 触屏再点一次 | 打开 | 插入 |

实现上有三个坑：

- `editor-picker.css` 是从 `userfiles.css` 分叉来的，`.sufm-grid-check` 在里面有三份历史规则（约 1179 / 2768 / 5517 行），后写的会把勾选框重新显示出来。面板的选择样式因此**统一追加在文件末尾**（同特异性后写的赢），要改就去末尾那一块改，别在前面改完发现没效果。
- 菜单层是 `document.body` 的子节点，不在 `#sufm-picker` 里面，所以它拿不到 `--sufm-*` 变量、也可能和用户中心那套菜单同页共存。`editor-picker-manager.js` 给这一层加了 `data-sufm-picker-menu="1"`，面板专属样式一律用 `[data-sufm-picker-menu] …` 限定。
- 双击插入依赖 `window.tinymce.get('post_content')`（或 `state.editor.insertContent`）。找不到编辑器时面板会 toast「找不到编辑器，请点一下正文再试」，不会静默什么都不做 —— 改这段时保留这条提示。

## 8. JS 结构与可扩展点

后台只有一个全局：

```js
window.SakuraAdmin = {
  page, root, ready, qs, qsa, on, delegate, closest,
  parseJSON, dataBlock, debounce, raf, format, events,
  data:    window.sakuraPage.data,      // 每个页面由 PHP 注入
  strings: window.sakuraPage.strings,
  api: { request, get, post, ajax, upload, SakuraApiError },
  ui:  { toast, confirm, busy, copy, labelTables, mediaPreview, openModal, hideModal }
};
```

- `window.sakuraPage`（`wp_localize_script` 注入）：`page / ajaxUrl / restUrl / nonce / data / strings`。
- **正常路径是 React 岛**：每个页面的 bootstrap JSON 由 `*_Payload.php` 生成，`assets/ui/src/{page}/index.jsx` 读它并 `createRoot()` 到 `.sakura-admin__main`；下表旧控制器的约定只在 bundle 缺失、走回退视图时成立。
- 旧页面控制器统一写法：`(function(window, document){ var admin = window.SakuraAdmin; if (!admin) return; … })(window, document);`
- **渐进增强是硬约定**：旧回退页没有对应 JS 时，仍必须是完整的设置表单（能保存、能看）。所以 JS 里不要再造一遍标记。
- `data-sakura-action="…"` 不是全局约定，而是**单页内**的约定：每个控制器自己 `admin.delegate(root, 'click', '[data-sakura-action="xxx"]', …)`。新增一个动作要连控制器一起写。
- 媒体库那三个脚本里，只有 `media-folders.js` 依赖 `media-views` / `media-grid`（Backbone/jQuery）；`media-modal-folders.js` 与 `media-new-folders.js` 都是原生 DOM。后台其余脚本没有 jQuery 依赖。
- **`media-folders.js` 替换列表 DOM 之后必须自己重新配对批量下拉。** 树形导航是 AJAX 的：`refreshMedia()`（`assets/media-folders.js:87`）把 `#posts-filter .wp-list-table` / `.tablenav.top` / `.tablenav.bottom` 三块 `replaceWith()` 换成新节点。而 WP 的「顶部与底部批量动作下拉联动」是 `common.js` 的 `marryControls()`（`wp-admin/js/common.js:1238`，`:1280` 调用）在 DOM ready 时对**当时那些节点**绑定一次 —— 节点被换掉，绑定就没了，新下拉是哑的。用户看到的现象是：在顶部选「违规下架」，底部还停在 `-1`。
  两条硬规则：① `refreshMedia()` 结束前必须调 `marryBulkControls()`（`:102`，用 `data-sufm-married` 防重复绑定）把两处重新配成一对；② 判断"用户选了哪个批量动作"时**只认 `select[name="action"]`**，`action2` 只是底部镜像（`WP_List_Table::current_action()` 读 `$_REQUEST['action']`，`wp-admin/upload.php:257`），任何以 `action2` 优先的实现都会在第一次树导航后失效。`askTakedown()` 提交前还要把两处都钉成目标动作，因为表单会把两个都发上去。
  `[1.28.7-beta-20 修；影响面不只下架——任何依赖底部下拉的批量操作在树导航后都会失效]`
- **媒体库是唯一下架入口，改它要守住「只有一份循环」。** 1.28.7-beta-21 曾加过一个独立的「媒体管理」页签，1.28.8-beta-1 删掉了（原因见 11 §10.4：够不够用比好不好维护更靠前）。所以 `assets/media-folders.js` 仍是唯一的下架 UI，它继续受上面那条 `marryControls()` 约束；而**动作逻辑不许再写第二份**——`Media_Hooks::handle_takedown()` 只把列表表格的 GET 提交翻译成 `Takedown::run()`，`operation_id` 的生成、按 owner 聚合、「先通知再判决」的顺序都在 `src/UserFiles/Services/Takedown.php` 里。往这里加功能时先问一句：这个改动会不会让循环出现第二份？
- 前台：`window.sufmData`（`sufm-front`）、`window.sufmFolders`（媒体库）、`window.SUFM_EDITOR`（编辑器面板）；弹窗是原生 `<dialog>`。

## 9. 手动调试清单

| 想知道 | 怎么做 |
|---|---|
| 当前页的页面 id | `document.querySelector('.sakura-admin').dataset.sakuraPage` |
| 某个令牌此刻的值 | `getComputedStyle(document.querySelector('.sakura-admin')).getPropertyValue('--g-accent')` |
| 我的规则有没有被解析（不是被覆盖，是压根没进 CSSOM） | `[...document.styleSheets].flatMap(s => [...s.cssRules]).filter(r => r.selectorText?.includes('card__kicker'))` |
| 哪个文件带的 `?ver=` | 元素面板看 `<link rel=stylesheet>` 的完整 URL |
| 线上是不是旧文件 | 用 `?ver=$(date +%s)` 抓一次，绕过 CDN 的 30 天缓存 |
| 选中态/悬停态为什么不生效 | 先确认状态类是不是被 JS 换过（如存储配置卡的 `is-active` / `is-current` 由 `assets/ui/src/storage/` 的配置组件切换），再确认选择器特异性 |
| 移动端断点 | 782px（WP 折叠）、1100px、900px、600px |
| 我改的规则明明写对了却没效果 | 同一个选择器可能在文件后段还有一份（`rg -n '\.sufm-grid-check' assets/userfiles.css`）。后写的赢，改前先 grep 出来，别只按行号改第一处 |

改完 CSS 之后**检查顺序**建议固定：`CSSOM 里有没有规则` → `getComputedStyle 的值对不对` → `截图看观感`。跳过前两步，很容易把「规则没解析」当成「被覆盖了」。

`userfiles.css` 这种四千多行的文件尤其要注意第三点：一处视觉（比如网格卡片的勾选框）可能同时被顶部的基础块和后面第二块「Grid card: …」覆盖。改之前 `rg -n '<选择器>'` 数一下命中几处，改完再看一眼计算值——1.28.7-beta-22 就是因为只改了前一处，勾选框在网格视图里仍然露着。

## 10. 新增文件的规范

1. 新页签的样式：放 `assets/ui/pages/{page}.css`，**不用改 PHP**，`Page_Assets` 自己会找到。
2. 新页面的内容区：源放 `assets/ui/src/{page}/`，产物 `assets/ui/dist/{page}.js`；在 `Page_Assets::ISLAND_BUNDLES` 登记后才算启用，旧视图只作为回退。
3. 新组件的样式：写进 `components.css`；只有一个页面用的，别放这里。
4. 新图标：放 `assets/ui/icons/*.svg`，用 `UI::lock_icon()` 那种「PHP 返回字符串 + 内联」或 `mask-image` 二选一，**同一张图只存一份**（不要在 PHP 里再抄一份 path 数据；React 侧用 `LockIcon` 复用同一段 path）。
5. 新的全后台资源（不进插件页也要加载的）**先问能不能并进 `base.css`/`components.css`**。目前只有 `admin-menu-icon.css` 一个先例，它只碰 `#adminmenu`。
6. 版本串自动生成，别手写；动完 `.php/.js/.jsx/.css` 按 AGENTS.md §5.1 把三处版本号 +1。
7. 前台新增内联 SVG：CSS 给尺寸（见 §7 的坑 2）。

## 11. 常见问题

**改了 CSS，刷新没变化。**
先看 `<link>` 的 `?ver=` 有没有变（变了说明服务器上是新文件，问题在浏览器/CDN）；再看 §9 的 CSSOM 检查；最后确认你的规则没被更具体的选择器压过。裸 URL 被 CDN 缓存 30 天，别用它判断。

**我的规则生效了，但页面别处坏了。**
十有八九是选择器写得太宽（`.card`、`input`、`svg`）。插件自己的样式全部从 `.sakura-admin` 或 `#adminmenu` 起头，你的覆盖也应该。

**`!important` 不起作用。**
那说明对手也是 `!important` 且特异性更高，或者规则根本没进 CSSOM（语法错误会让整条规则被丢弃——**数括号平衡不能证明规则有效**，要用 CSSOM 看）。

**子主题里写的后台 CSS 在前台也生效了。**
`admin_enqueue_scripts` 只在后台跑；如果你把 `wp_enqueue_style` 挂在子主题的 `wp_enqueue_scripts` 上，它会跟着前台走。分开挂。

**样式在源站对、在生产错。**
两种可能：CDN 缓存（§3.2），或者生产是 git checkout、文件没同步（看 `git -C 插件目录 status`）。

**表格在手机上挤成一列/溢出。**
`components.css` 的 `.table--responsive` 依赖 JS（`admin.ui.labelTables`）把表头写进 `data-label`；没有 JS 时不要指望折叠效果。
