# 14 后台页面契约

> 适用：`src/Admin/App_Manifest.php` 的 `ROUTES` 里的每一条后台路由（15 条）。
> 本篇是判据，不是建议：新增页面、迁移旧页面、改 payload 都先对照这一篇。写法规范见 [12-React代码规范](12-React代码规范.md)，视觉规范见 [03-后台UI](03-后台UI.md)。

## 0. 一句话

一个页面 = **服务端算好的 payload** + **一个 React App** + **一组 REST 动作**。首屏和壳内导航读同一份 payload；写只走 REST；动作后不重建文档。

## 1. payload 六键（缺一即不合约）

每个页面的 bootstrap 与 `GET /pages/{page}` 必须返回同一份数组，至少包含：

| 键 | 类型 | 规则 |
|---|---|---|
| `page` | array | 页面描述：`id` / `module` / `tab` / `island` / `skeleton`。`id` 必须等于路由 id |
| `head` | array | 由 `UI\Page::head_data( $page )` 产出，PHP 与 React 共用 |
| `chrome` | array | 由 `Shell::header_data( $module, $tab )` 产出 |
| `cards` | array | **有序列表**，每项至少 `{id}`；顺序必须与 `Layout::PAGES` 的 `order` 一致（放置信息由 `Layout::card()` 下发） |
| `strings` | array | 本页由 JSX 直接读取的散文案（按钮、aria-label、提示语）；`kicker` 属于卡片，见 §7。JSX 里不写中英文 |
| `rest` | array | 至少 `url` / `nonce` / `refresh`，见 §3 |

允许的额外顶层键只有：`version`、`tab`、`alerts`、`notice`、`data`、`sections`（与 `Payload_Contract::OPTIONAL` 一致）。

- **卡数据跟着卡走**：`cards` 的每一项可以携带它自己的数据（`values` / `fields` / `rows` …），React 把它整块传给 `Card`。
- **跨卡共享数据放 `data`**：例如页码、总数、扫描视图。不要为每张卡复制一份；需要按卡查找的零散数据放 `sections`。
- **禁止**再新增本页专属的顶层键（历史代码里的 `config` / `view` / `rows` / `logs` / `snapshot` / `card` 都属于要收进 `data` / `sections` 的形态）。

## 2. 首屏与 REST 同源

- 首屏：视图打印 `<script type="application/json" id="sakura-*-bootstrap">`，内容就是合约 payload。
- 导航：`GET /wp-json/sakura-tools/v1/pages/{page}` 返回**同一个 builder** 的结果，不写第二个 serializer。
- `Page::render()` 统一打印 `#sakura-app-manifest`；payload 不再自带 `app`。

## 3. rest 的形状

```php
array(
  'url'     => esc_url_raw( rest_url( 'sakura-tools/v1/storage' ) ), // 本页动作的基础 URL
  'nonce'   => wp_create_nonce( 'wp_rest' ),
  'refresh' => esc_url_raw( rest_url( 'sakura-tools/v1/pages/storage-connection' ) ),
  // 额外端点用具名键；值是一个子数组（可含 url / nonce / 多个动作），
  // 其中每个 URL 必须是绝对 URL，不要在前端拼字符串
  'export'  => array( 'url' => ... ),
)
```

- **前端禁止用正则或字符替换从 `url` 推导其它端点**；需要什么就下发什么。
- `refresh` 由 `Payload_Contract::normalize()` 自动补，builder 可以不管。

## 4. 写操作

- 只允许 REST（`register_rest_route`）。**禁止新增 `wp_ajax_` 处理器**；旧页面的 admin-ajax 写操作随页面迁移一并删除。
- 读也可以用 REST；首屏不走 REST。
- 权限与页面门禁同源：`permission_callback` 必须复用 `App_Manifest::can_view( $page )`，不要再写第二套判断。
- 动作响应必须包含被改动的数据（`sections[card.id]` / `data` 的对应片段）与新 `notice`；前端用它覆盖本地状态。
- **动作后禁止 `location.reload()`**。需要整页刷新数据时调用 `refresh( rest )`（GET `rest.refresh`）并合并结果。

## 5. 状态与保存

- `saved` / `draft` 两份；保存成功后两份都换成**响应里的值**（服务端会 clamp）。
- props → draft 的复位用 `key` 或「渲染期比较后 setState」，**不用 `useEffect` 同步**。
- 派生状态在渲染期算；`useEffect` 只做外部系统订阅与清理。

## 6. 弹窗

- **结果提示**（保存成功/失败、探测结果）：共享 `Prompt`，文案来自 `strings`。
- **确认与选择**（删除、输入确认词、切换桶、选择空间）：共享 `Dialog`（`assets/ui/src/shared/Dialog.jsx`）。禁止页面内再写第三个弹窗实现。
- 两者都只在 `.sakura-admin` 内 portal，必须支持 Esc、焦点回触发元素、Tab 不逃逸。

## 7. 文案与 URL

- 所有可见文案（含按钮、aria-label、卡片 kicker）来自 payload：散文案放 `strings`，`kicker` 放对应卡片的 `cards[].kicker`（`Card` 直接渲染这一项）；JSX 里不写中英文。
- URL / nonce / option 名 / 字段 id 一律来自 payload。
- 中文兜底只允许 `strings.x || '……'` 形式，且该键必须真的存在于 `strings()`。

## 8. 契约测试

`tests/Admin/PageContractTest.php` 检查全部 15 条路由，只有一套标准：

- **STRICT（15 条，已迁移）**：`system-settings`、`image-rules`、`image-thumb`、`image-backup`、`image-stats`、`storage-connection`、`storage-sync`、`storage-deletes`、`storage-rewrite`、`storage-cost`、`files-settings`、`files-queue`、`files-log`、`zibll-performance`、`files-zibll`。逐条断言：
  1. payload 六键齐全；
  2. `cards` 是非空有序列表，每项有 `id`；
  3. `rest.url` / `rest.nonce` / `rest.refresh` 为非空字符串；
  4. 顶层不出现 `config`，也不出现未登记的额外键。

加页面时先让它过 STRICT，再谈 UI。
